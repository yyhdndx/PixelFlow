# 阿里云服务器部署记录

验收日期：2026-10-19。部署提交：`4c23e6cf3b107b2d36ad0c69cf4d42043362405d`。

## 当前运行环境

- Alibaba Cloud Linux 3；Java 17、Python 3.11、MySQL Community 8.4.11。
- 公网 API：`http://8.140.36.87`，由 Nginx 转发。
- Java：`127.0.0.1:8080`；Python：`127.0.0.1:8001`；MySQL：`127.0.0.1:3306`。
- `mysqld`、`pixelflow-java`、`pixelflow-python`、`nginx` 均由 systemd 管理并开启自启。
- 两端服务的 `service.d/mysql.conf` 增加 MySQL 启动依赖和顺序。
- 版本目录：`/opt/pixelflow/releases/4c23e6cf3b107b2d36ad0c69cf4d42043362405d`；`/opt/pixelflow/current` 指向该目录。

## 数据与配置

- Java 业务库/账号：`pixelflow_app`；Python 分析库/账号：`pixelflow_analytics`。两个账号仅拥有各自数据库权限。
- MySQL 数据目录：`/var/lib/pixelflow-mysql`；配置：`/etc/my.cnf`。
- MySQL 仅绑定回环地址，关闭 X Protocol；InnoDB 缓冲池 128 MB，最大连接数 40，适配当前约 2 GB 内存的机器。
- 服务环境文件仍是 `/etc/pixelflow/java.env` 和 `/etc/pixelflow/python.env`，已切换 MySQL，原 JWT、服务间认证令牌及公网素材地址保留。
- MySQL 管理连接配置保存在 `/etc/pixelflow/mysql-admin.cnf`。包含凭据，仅 root 可读；不提交 Git、不复制到聊天。
- 原 H2 数据、SQLite 数据和旧发布版本仍保留，不再由当前服务读写。

## 旧 MariaDB 与备份

旧实例是 MariaDB 10.5，包含 `seuoj`、`studentDatabase`。经授权停用，安装 MySQL 时替换了 MariaDB 服务相关软件包。没有将这两个旧库导入 PixelFlow，也没有覆盖它们的原数据目录 `/var/lib/mysql`。

迁移前后备份统一保存在 root 私有目录：

```text
/var/backups/pixelflow/mysql-cutover-20261018-01/
  mariadb-all.sql         旧 MariaDB 全库逻辑备份
  mariadb-data/           停机后的 MariaDB 数据目录副本
  pixelflow-data/         旧 H2/SQLite 目录副本
  pixelflow/              切换前的服务环境配置
  previous-release.txt   旧版本目录
  database-packages.txt  切换前的数据库软件包清单
  mysql-after-cutover.sql 迁移验收后的 MySQL 业务库与分析库备份
  mysql-active-config/   切换后的 MySQL 与服务配置
```

目录名称沿用 10 月 18 日开始迁移时的名称。恢复旧 MariaDB 需要匹配版本的 MariaDB 软件和配置，不能用 MySQL 直接打开旧数据目录。PixelFlow 回滚可使用保留的旧版本、旧环境文件和旧 H2/SQLite；若新库已有后续写入，必须先处理数据差异。

## 验收结果

- Java 导入 6 个账号、33 条帖子、3 个种子批次；事件源标识保留。
- Python 旧库没有事件或画像，迁移 checkpoint 后成功调用 Java 增量导出，来源绑定正确。
- Nginx 公网健康接口返回 UP，Feed 返回 33 条帖子，图片可访问。
- 实际验证注册、登录、本人资料、草稿写入和 Java → Python 本人画像代理。
- 实际验证 Python → Java 增量同步及分析状态接口。
- 验收使用的临时账号、会话和草稿已删除；没有改动原有演示账号和帖子。
- 公网 `/api/internal/**`、`/api/admin/**` 继续返回 404。

Flyway 在 MySQL 8.4 上仍打印“版本高于其已验证范围”的提示，但 V1–V6 建表、数据导入及实际接口读写均成功。后续依赖维护时再评估 Flyway 升级，不使用 repair 或忽略迁移失败来绕过问题。

## 后续运维

代码推送不会自动发布，仍按“新版本构建 → 切换 current → 重启 → 验收”流程更新。此次提供了迁移前后备份；尚未配置每日自动备份和 Python 周期分析定时器，不应把服务常驻等同于分析任务自动执行。

详细迁移流程见 [MySQL 部署与迁移](MySQL部署与迁移.md)。Alibaba Cloud Linux 的 `$releasever` 为 3，而 MySQL 官方仓库需要 EL8 路径；本次已将新增 MySQL 仓库的 `/el/$releasever/` 修正为 `/el/8/`，只启用 MySQL 8.4 LTS 仓库。不要全局覆盖系统的 releasever，否则会影响阿里云系统软件源。
