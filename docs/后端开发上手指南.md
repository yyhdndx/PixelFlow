# 后端开发上手指南

面向领取 Java / Python issue 的同学。先按本文在本机跑通，再阅读对应模块的接口说明。本文的本地命令使用 Windows PowerShell；云服务器的安装和更新由部署负责人执行。

## 1. 环境与版本从哪里看

| 项目 | 团队开发环境 | 版本依据 |
| --- | --- | --- |
| Java | JDK 17 | `server/pom.xml` 的 java.version |
| Maven | 3.6.3 或以上 | 独立 Maven 工程，没有 Maven Wrapper |
| Python | 3.11 | pyproject.toml 声明最低 3.10，团队统一 3.11 |
| MySQL | 8.4 LTS | 云端已验证 8.4.11；不要用 MariaDB 或 MySQL 5.7 替代 |
| Java 库 | Spring Boot 等 | `server/pom.xml` 与父 POM 依赖管理 |
| Python 库 | 固定版本安装 | `intelligence/requirements-lock.txt`；直接依赖同时声明于 pyproject.toml |

代码要求、团队统一版本与云端实际部署是三个不同概念。`git rev-parse HEAD` 查看本地提交；[服务器部署记录](../deploy/服务器部署记录.md)记录最近一次云端验收的提交。仓库新增提交不意味着服务器同步更新。

当前云端部署记录：2026-10-19，提交 `4c23e6c`。后续发布必须更新记录；仅修改文档的提交可以比运行版本新。Android 共享联调地址为 `http://8.140.36.87`。

## 2. 领取 issue 与开发边界

```powershell
git clone https://gitee.com/yyhSEU/pixel-flow.git
cd pixel-flow
git switch -c feature/issue-编号-简述
java -version
mvn -version
python --version
mysql --version
```

确认 Maven 实际使用 JDK 17，`python` 指向 Python 3.11；Windows 多版本共存时也可使用 `py -3.11` 创建虚拟环境。未安装 MySQL 的同学先安装 MySQL Community Server 8.4，确认本机实例已启动。

- Java 负责账号、帖子、互动、权限、业务数据及分析导出接口。
- Python 负责事件同步、画像、推荐与 Skill；通过接口访问 Java，不直接访问 Java 数据库。
- 本期没有 Web 开发任务，`admin-web/` 是历史预留目录，无须启动或安装依赖。
- 日常开发使用自己电脑上的数据库；云端只用于团队联调，不对云端执行自动测试、清库或试验性迁移。

基础 Java 接口可以单独运行。画像代理需要 Python；Python 的账号验证、数据同步和推荐预览需要 Java。建议需要跨服务联调时在本机同时运行两端。不要把本地 Python 指向公网 Java：公网 Nginx 按设计屏蔽内部导出接口。

## 3. 创建本地数据库

使用本机 MySQL 管理员执行 `mysql -u root -p`，在 SQL 终端执行下面语句。两个密码占位符需先替换为自己生成的独立密码；这些是本地账号，不使用服务器凭据。以下是首次创建命令，已建库时不要重复创建或删除重建。

```sql
CREATE DATABASE pixelflow_app CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_bin;
CREATE DATABASE pixelflow_analytics CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_bin;
CREATE USER 'pixelflow_app'@'localhost' IDENTIFIED BY '<本地Java数据库密码>';
CREATE USER 'pixelflow_analytics'@'localhost' IDENTIFIED BY '<本地Python数据库密码>';
GRANT ALL PRIVILEGES ON pixelflow_app.* TO 'pixelflow_app'@'localhost';
GRANT ALL PRIVILEGES ON pixelflow_analytics.* TO 'pixelflow_analytics'@'localhost';
```

应用会管理各自的建表和升级，首次开发不需要运行 H2/SQLite 迁移工具。账号只拥有各自库的权限，包含应用启动所需的建表权限。

## 4. 填写本地配置

仓库根目录执行：

```powershell
Copy-Item server/.env.example server/.env
Copy-Item intelligence/.env.example intelligence/.env
```

上述复制仅首次执行，避免覆盖自己已经填写的 `.env`。编辑两个文件，替换全部 `CHANGE_ME` 值。

- Java 的 DB_PASSWORD 填原始数据库密码；Python 的 ANALYTICS_DB 把密码放在 URL 中，需要对密码部分进行 URL 编码，例如 `@` → `%40`、`!` → `%21`。
- 生成三份不同随机值，分别作为 JWT 密钥、分析导出令牌、Python 运维令牌。每个至少 32 个 ASCII 字符。
- 两个文件中的 PIXELFLOW_ANALYTICS_EXPORT_TOKEN 必须相同；它与 PIXELFLOW_INTELLIGENCE_TOKEN 必须不同。
- `.env` 被 Git 忽略；`.env.example` 可以提交。示例不含真实凭据，不向同学共享服务器 root 密码。

可在自己终端生成三个随机值后填入文件，不要粘贴到 issue：

```powershell
python -c "import secrets; print('\n'.join(secrets.token_hex(32) for _ in range(3)))"
```

两端都不会自动读取 `.env`。下面启动命令显式导入环境变量；文件使用 `KEY=value` 格式，不加引号、不写 `export`、不使用行尾注释。IDE 启动时则在 Run Configuration 中设置相同变量。

## 5. 启动服务

第一个 PowerShell 窗口，从仓库根目录进入 Java：

```powershell
cd server
Get-Content .env | ForEach-Object {
    if ($_ -match '^([A-Z][A-Z0-9_]*)=(.*)$') {
        [Environment]::SetEnvironmentVariable($Matches[1], $Matches[2], 'Process')
    }
}
mvn clean package
java -jar target/pixelflow-server-0.1.0.jar
```

初次需要演示内容时，在启动前设置 `$env:PIXELFLOW_SEED='true'`；成功生成后将 `.env` 中开关保持 false。演示库有 6 个账号和 33 条帖子，但没有可共享的固定登录密码，请通过注册接口或 Android 注册自己的账号。需要测试审核的同学再按 [Java README](../server/README.md)配置本地管理员。

第二个 PowerShell 窗口，从仓库根目录进入 Python：

```powershell
cd intelligence
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m pip install --no-deps -e .
Get-Content .env | ForEach-Object {
    if ($_ -match '^([A-Z][A-Z0-9_]*)=(.*)$') {
        [Environment]::SetEnvironmentVariable($Matches[1], $Matches[2], 'Process')
    }
}
.\.venv\Scripts\python.exe -m uvicorn pixelflow_intelligence.api.app:create_app --factory --host 127.0.0.1 --port 8001
```

虚拟环境只需首次创建；依赖变更后重新安装锁定依赖。Windows 无需激活 venv，直接用上面的完整解释器路径即可。

本机启动不依赖 Nginx。第三个窗口检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8080/health
Invoke-RestMethod http://127.0.0.1:8001/health
Invoke-RestMethod 'http://127.0.0.1:8080/feed/?count=3&accept_video_clip=true'
```

`/health` 只是存活检查。还需注册登录、读取 Feed，并按自己的 issue 验证实际读写接口。未开启种子时 Feed 为空是正常情况。

Android 模拟器访问本机 Java 使用 `http://10.0.2.2:8080`；此时种子生成前也应将 PIXELFLOW_PUBLIC_BASE_URL 设成这个地址，确保图片可访问。真机本地联调见 [Android 联调说明](android/Java服务联调说明.md)。只联调云端时 Android 使用公网地址，不必在电脑启动后端。

## 6. 同步和画像不是自动后台任务

保持 Java、Python 运行，在已导入 Python `.env` 的另一个终端中执行：

```powershell
cd intelligence
Get-Content .env | ForEach-Object {
    if ($_ -match '^([A-Z][A-Z0-9_]*)=(.*)$') {
        [Environment]::SetEnvironmentVariable($Matches[1], $Matches[2], 'Process')
    }
}
$env:PIXELFLOW_MAINTENANCE_URL='http://127.0.0.1:8001'
.\.venv\Scripts\python.exe -m pixelflow_intelligence.maintenance --budget-seconds 120
```

命令使用 PIXELFLOW_INTELLIGENCE_TOKEN 调用同步和重算接口；需观察最终状态是否完成。没有用户行为时画像为空/冷启动是正常情况。当前云端尚未启用周期分析定时器，服务常驻不代表它定期计算画像。

## 7. 测试与数据库升级

| 检查 | 命令（对应模块目录内） | 使用的数据库 |
| --- | --- | --- |
| Java 快速测试 | `mvn test` | 测试内指定的 H2，不等同于 MySQL 验证 |
| Python 快速测试 | `.\.venv\Scripts\python.exe -m pytest -q` | 临时 SQLite / 固定样本，未配置 MySQL 时集成测试跳过 |
| MySQL 集成测试 | 配置测试环境变量后再运行上述命令 | 专门的可清理测试库，绝不能指向开发库或云端库 |

MySQL 测试库必须以 `_test` 结尾，且与开发库分开。Java 环境变量为 MYSQL_TEST_URL、MYSQL_TEST_PREFERENCES_URL、MYSQL_TEST_STATS_URL（个人主页统计）、MYSQL_TEST_MIGRATION_URL 及 MYSQL_TEST_USER / MYSQL_TEST_PASSWORD；Python 为 MYSQL_TEST_ANALYTICS_DB。迁移测试的目标库每次必须为空。准备和运行细节见 [MySQL 部署与迁移的测试说明](../deploy/MySQL部署与迁移.md#8-后续备份与开发)。这些环境变量仅在测试终端配置，不放进日常服务 `.env`。统计接口的用例及运行命令见 [个人主页统计验收](testing/个人主页统计验收.md)。

Java 修改表结构追加 `server/src/main/resources/db/mysql/V7__描述.sql` 等新版本，并维护 H2 测试兼容脚本；多人开发先协调版本号。Python 在 `analytics/mysql_schema.py` 中追加 MIGRATIONS 版本。不能修改已经在共享环境执行过的迁移，不能删除数据让测试“通过”。接口 issue 涉及数据库变化时，需要说明旧数据如何升级和失败如何恢复。

## 8. issue 交付与发布

在 issue 中写清：对应页面/场景、调用示例、响应字段、错误处理、测试结果，以及新增环境变量/依赖/数据库迁移。跨服务字段变化同步更新相关契约即可，不要求为每个小 issue 编写整套接口规范。

- Java HTTP 约定：[java-api.yaml](../contracts/http/java-api.yaml)。
- Python HTTP 约定：[python-analytics.md](../contracts/http/python-analytics.md)。
- 两端具体实现：[Java README](../server/README.md)、[Python README](../intelligence/README.md)。

提交前检查 `git diff`，不提交 `.env`、数据库文件、虚拟环境、构建产物或 IDE 私有配置。推送功能分支并按团队流程评审合并，由部署负责人统一发布，不在运行中的服务器目录直接改代码。

服务器更新需要新目录构建、必要的数据升级、切换 current、重启、接口验收，并更新部署记录。不要把 git push 当作部署成功；同样不要在共享服务器执行新成员首次安装或旧数据迁移命令。

## 9. 常见问题

| 现象 | 优先检查 |
| --- | --- |
| Access denied / 数据库连接失败 | MySQL 是否启动、端口、账号密码、账号 host 是否匹配；是否导入了 `.env` |
| Python 找不到 pixelflow_intelligence | 使用 `.venv` 的解释器，并完成 `pip install --no-deps -e .` |
| Python URL 连库失败 | 密码是否只对 URL 部分编码；不要把整个 URL 编码 |
| Flyway 校验失败 | 是否修改旧脚本或分支迁移版本冲突；不要直接 repair |
| 同步 401 / 503 | 两端导出令牌一致、运维令牌独立、Java 本机地址可达 |
| 云端内部接口 404 | Nginx 的预期隔离；本地开发启动本地 Java |
| health 正常但画像为空 | 是否产生行为事件并执行同步/重算 |
| 应用改代码后没有变化 | 本机 Java 是否重新构建；云端是否真正发布了对应提交 |

历史 CentOS 指南保留为参考，不作为当前新成员入口。当前实际部署、版本和备份位置以 [服务器部署记录](../deploy/服务器部署记录.md)为准。
