## 两项容易误判的工作

1. **任务 15 不是 Agent 验收。** 当前任务定义只是包装 Python 推荐预览，Python 不可用时返回 503。原始 US-05 还要求自动回退到热门或时间 Feed，以及策略版本、traceId 和可查询执行过程。需明确在哪一层实现安全降级，复用 Java 可见性和负反馈过滤，不能靠显示“服务不可用”替代。
2. **MCP 工具不等于完整 Agent。** 新分支声明规划由外部 Agent 客户端承担。它可以成为工具基础，但原始“Android→Java→Python 推荐 Agent”的链路尚未完成。若最终改用外部 Agent 做课程演示，必须明确记录架构/验收范围变更；不能用工具调用日志代替完整计划、Skill 执行和失败降级轨迹。

## 范围处理

- 已明确调整：本期只做 Android、Java、Python，不额外给 Android 负责人安排 Web 开发。见 [交接说明](新对话交接说明.md) 和 [admin-web 状态](../admin-web/README.md)。原需求第 10 节仍写“完整 Web 业务系统”，需在第 1 天核对课程口径并整理变更说明；若课程硬性要求 Web，则当前安排存在范围冲突。
- 不再扩张：完整评论、搜索、消息、私信、复杂推荐模型、向量库、多 Agent、复杂动画、额外首页装修。这些不应挤占智能主线和验收时间。
- 视频上传是原功能要求，不能误称已经完成；建议本轮缩减为图片创作，保留现有视频浏览，列入范围变更。
- 头像属于已有未交付成果：本地 `feature/user-avatar` 的 `fa23b44` 未合入。审查后尽早整合，不重复开发；V8 与已应用 V9 的迁移顺序需单独处理，保留备份和部署门禁。

## 最终验收主线

1. A 注册登录，浏览与互动；事件进入 Python，产生可查询画像版本。
2. 推荐 Agent 选择计划并组合 Skill，Android 显示推荐理由；按 traceId 查到计划、调用、耗时和版本。
3. A 不感兴趣/撤销、抑制主题/关闭个性化，下一次推荐遵守偏好，不包含已下架或无权查看作品。
4. A 创建图片草稿，预览 AI 标题/标签与安全建议，确认后写入；调用失败仍保留原稿。
5. 受控管理员审核，B 在 Feed 看见作品并收藏；A 撤回后，B 无法继续访问非公开内容。
6. 注入 Python/Skill 超时，基础登录、普通 Feed、人工创作可用，推荐按约定降级并留下记录。
7. 验证真实 Redis 限流触发、过期恢复和身份隔离；给出性能测量与版本化评测报告。

最近 Android 证据为 [10 月 29 日验收](testing/前端推送验收-2026-10-29.md)：68 项 JVM、32 项专项设备测试通过。它们证明相应代码回归通过，不等于最终云端/物理手机全链路已验收。离线规则评测见 [评测口径](../intelligence/src/pixelflow_intelligence/evaluation/README.md)，合成样例命中率不得称为真实推荐准确率提升。
