# F03 收藏生命周期修复验收

日期：2026-10-25。对应 [首次独立验收](Claude-Code-F03验收-2026-10-25.md) 的 P1：详情销毁会取消用户已确认、仍在队列中的收藏写入。原始失败 XML 和源码快照保留，不覆盖历史证据。

## 修复范围

- `WorkDetailActivity` 将可取消的收藏读取与写入分开；停止/销毁页面只取消读取，页面退出不再取消已确认写入。
- 每次返回/重建先清空旧收藏状态，再排队读取服务端；读取完成前禁止新的收藏写入。页面版本和账号会话版本拦截旧回调，防止旧账号结果覆盖当前界面。
- 写入报错后先核对服务器；核对失败时按钮仅重试读取，不再次提交同一写入。提示文字使用实际回读的收藏结果。
- 全链路设备测试另发现一个已有导航缺陷：没有列表截图时，退出动画把 `CoordinatorLayout` 强转成 `FrameLayout`，导致系统返回键崩溃。现改为通用 `ViewGroup` 添加背景，测试保留真实返回路径。
- 增加收藏按钮的加载、重读、收藏/取消收藏无障碍说明，以及正式设备回归 `FavoriteDetailReviewTest`。本轮未修改 Java/Python 业务代码。

## 正式设备回归

| 场景 | 主要断言 |
| --- | --- |
| 正常收藏 | 服务器收到一次写入，详情回读已收藏 |
| 队列忙时点击并关闭详情 | 写入未被销毁取消，最终状态正确 |
| 写入未返回时退后台再恢复 | 核对期间按钮禁用，重复点击不增加写入 |
| 排队写入时页面重建 | 写入保留，新页面读取最终结果 |
| 读取中停止并返回 | 清空旧状态并重新读取，不发起写入 |
| 服务器提交成功但写响应为 503 | 重新读取已提交结果，不补发写入 |
| 写入及后续核对均报错 | 先重试读取；读成功后才允许新的修改 |
| 写入未返回时切换账号 | 旧账号回调丢弃，新账号显示自己的状态 |
| 收藏列表→详情→取消→立即返回 | 使用真实导航与返回键，列表刷新为空，服务器仅收到一次取消 |

测试环境：Windows、JDK 17（Android Studio JBR）、Pixel_2_API_36 / Android 16。测试通过设备内 MockWebServer 控制队列和响应，没有读写云端账号或数据。
