## 交互行为

1. 保留综合优化、优化标题、润色正文、生成文案、推荐话题五个选项。首次弹窗只保留一个要求输入框，草稿非空时可以不填；不再询问目标读者。只有图片时仍需用户填写文字，当前接口不理解图片。
2. 每次标题、正文最多各一项；话题是一组标签。非当前目标的结果区域隐藏。综合优化仍允许分别采纳标题、正文和话题。
3. 结果预览内可填写新要求并继续修改。请求携带原始草稿、当前这一版和本次要求，不携带整段历史。操作目标保持不变。
4. 主动生成使用新任务身份；页面恢复继续订阅原任务，不因重建重复请求。连续点击期间只启动一个运行中的任务。
5. 修改期间保留上一版。失败、取消或任务过期不会删除已经得到的预览；运行期间禁用采纳，停止后仍可使用上一版。最后一份预览随本地草稿保存，不新增历史版本列表。
6. 草稿发生变化时保留旧建议，禁止直接采纳或继续基于旧稿修改。可复制参考，也可打开要求弹窗，按当前草稿重新生成。
7. 采纳只改本地草稿；新增撤销，恢复采纳前标题和正文。若采纳后又编辑，撤销需要明确确认。只保留最近一次采纳的恢复点。

润色正文必须有正文；草稿和要求同时为空时，不发起生成。无模型配置时仍保留首次规则建议，但继续修改明确返回不可用，避免规则模板冒充理解修改要求。

## 接口

沿用 `POST /api/agent/create-assist`，新增可选 `previous_result`：

```json
{
  "draft": {"title": "原始标题", "content": "原始正文", "tags": []},
  "goal": "polish_content",
  "prompt": "更口语化，保留具体经历",
  "previous_result": {"title": "原始标题", "content": "上一版正文", "tags": []}
}
```

首次请求省略 `previous_result`；有该字段时 `prompt` 必须非空。`audience` 保留以兼容旧调用方，新界面不再填写。响应继续使用候选数组，但标题、正文数组最多一项；正文上限与草稿统一为 5000 字，模型截断仍按失败处理，不采纳半截结果。

契约见 `contracts/http/java-api.yaml`。发布时先同步 Python、Java，再使用新 Android 客户端；旧后端不认识 `previous_result`，不能只更新客户端就验证继续修改。部署后还需用真实模型复核改写质量与长文耗时。
