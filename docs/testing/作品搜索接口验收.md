## 匹配与调用

q 去首尾空白后按 Java String.length 的 UTF-16 单位校验1–60；可去掉一个开头 `#`，剩余不能为空。整体短语不拆词。大小写不敏感，匹配标题前缀或正文 `#` 后的前缀；不匹配普通正文。`%`、`_`、`!` 做 LIKE 字面转义，采用 `!` 作为 ESCAPE，反斜杠为普通字符。

```http
GET /api/search/posts?q=%E6%91%84%E5%BD%B1&count=1
GET /api/search/posts?q=%23%E6%91%84%E5%BD%B1&count=1&cursor=10
GET /api/search/posts?q=%20%20
```

前两例游客可用，登录用户可附 `Authorization: Bearer <本次登录令牌>`；第三例400 INVALID_ARGUMENT。无效/停用令牌仍401。

```json
{"status_code":0,"post_list":[],"has_more":0,"next_cursor":null}
```

非空项直接复用 Post。has_more 为数字0/1，有下一页时next_cursor为本页最后作品ID字符串。按数字ID倒序、id < cursor续页，不承诺按create_time字段严格排序。首屏不排除最大long ID。默认同时返回图片、视频。

## SQL 与执行计划

生产查询原文（首屏不含游标条件；续页包含）：

```sql
SELECT p.*,u.nickname,u.avatar FROM posts p JOIN users u ON p.author_id=u.id
WHERE p.status='PUBLISHED' AND u.enabled=TRUE
AND (LOWER(p.title) LIKE ? ESCAPE '!' OR LOWER(p.content) LIKE ? ESCAPE '!')
-- 续页：AND p.id<?
ORDER BY p.id DESC LIMIT ?
```

为适配现有二进制排序规则，查询使用LOWER，输入以Locale.ROOT小写。它也限制了普通title前缀索引的可用性；加上正文OR条件，不能声称整个搜索查询使用标题索引。标题索引存在及30字符前缀由information_schema自动断言。

MySQL专项对以上完整SQL输出 SEARCH_EXPLAIN_FIRST / SEARCH_EXPLAIN_CURSOR，参数分别为 `摄影%`、`%#摄影%`、21，以及续页cursor=10。两名测试用户、两条公开作品的本地实测计划：

|页|表|type|key|rows|Extra|
|---|---|---|---|---|---|
|首屏|p|ref|posts_feed|2|Using where; Using temporary; Using filesort|
|首屏|u|ALL|null|2|Using where; Using join buffer (hash join)|
|续页|p|range|PRIMARY|1|Using where; Backward index scan|
|续页|u|eq_ref|PRIMARY|1|Using where|

此计划来自小型确定夹具，只证明真实查询和索引迁移可执行，不是大规模性能结论。LIMIT约束结果数，不约束所有候选扫描成本；标题单条件计划不能替代完整OR计划。无强制索引或表结构优化。
