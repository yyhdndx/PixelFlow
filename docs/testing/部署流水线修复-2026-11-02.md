# 部署流水线修复（2026-11-02）

## 问题与修改

GitHub 最近多次运行在 Python 测试收集时因 `ModuleNotFoundError: No module named 'mcp'` 失败，正式部署被跳过。CI 原来只安装 test extra，而 MCP 位于独立 extra。现改为安装 `[test,mcp]`，并在耗时的 Java 测试之前校验依赖与模块导入。

另外，线上手动发布 `kimi-4` 缺少源码迁移目录，旧脚本直接比较目录会错误阻断。现从新旧实际运行的 Spring Boot JAR 读取 MySQL 迁移，比较完整名称集合及 SHA-256；源码目录若存在，还必须与自己的 JAR 一致。没有移除数据库结构变化门禁，也没有重新执行或修改生产迁移。

JAR 缺失、损坏、不含迁移、源码与包不符，以及新增、删除、重命名或修改迁移，均在停止服务前失败。Python schema 比对、归档校验、发布锁、服务健康检查和应用回滚保持生效。
