# MCP 演示操作手册（2026-11-13）

面向答辩现场演示外部 MCP 接入。核心结论：**MCP 演示必须用一个真正支持 MCP 的外部客户端完成授权与工具调用**，只在 App 里用 Copilot、或由内部脚本直接调 Python 函数，都不算 MCP 演示（对齐 `docs/答辩演示脚本-20261112.md` 六 C）。

## 一、现状（本日实测）

| 项 | 状态 | 说明 |
| --- | --- | --- |
| 云服务器 `http://8.140.36.87/health` | 200 UP | Java 后端正常 |

**结论**：Python 侧 MCP 服务本体是好的；卡点只在「云服务器 Nginx/进程」与「本地 MySQL 凭据」两处环境问题，以及「外部客户端」这一演示环节。

- 审计日志 `tmp/mcp-audit.jsonl` 已记录每次调用（账号、工具、耗时、query 哈希）。
- 复用脚本：`tmp/mcp_client_demo.py`（凭据从 `PF_USER`/`PF_PASS` 环境变量读取，不落盘）。

## 二、客户端选择（推荐 Cherry Studio）

- **Cherry Studio**（首选）：免费、Windows 原生、支持远程 MCP + OAuth 授权，答辩现场最省事。
- Claude Desktop：MCP 官方参考客户端，评审认可度高，但需 Claude 账号。
- Cursor / Trae：IDE 内置，适合开发视角，演示场景略绕。

## 三、云服务器修复清单（给持有服务器 SSH 私钥的同学）

> 授权账号不可用时，本节交给运维同学执行；不改业务数据，只补 MCP 服务与 Nginx 路由。

1. 确认 MCP 进程与端口：

   ```bash
   systemctl status pixelflow-mcp --no-pager || echo "no unit（可能是手动进程）"
   ss -lntp | grep 8765
   ```

2. 环境变量 `/etc/pixelflow/mcp.env`（600 root:root）：

   ```ini
   PIXELFLOW_MCP_JAVA_URL=http://127.0.0.1:8080
   PIXELFLOW_MCP_PUBLIC_URL=http://8.140.36.87
   PIXELFLOW_MCP_AUDIT_LOG=/var/log/pixelflow/mcp-audit.jsonl
   ```

3. Nginx 增加路由（`contracts/mcp/README.md` 原样）并 reload：

   ```nginx
   location ~ ^/(mcp|authorize|token|register|revoke|oauth|\.well-known) {
       client_max_body_size 12m;
       proxy_pass http://127.0.0.1:8765;
       proxy_http_version 1.1;
       proxy_set_header Host $host;
       proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
       proxy_set_header X-Forwarded-Proto $scheme;
       proxy_read_timeout 120s;
       proxy_buffering off;
   }
   ```

   ```bash
   sudo nginx -t && sudo systemctl reload nginx
   ```

4. 验收（两个都要 200，且返回的是 MCP 元数据、不是「请先登录」）：

   ```bash
   curl -s http://127.0.0.1:8765/.well-known/oauth-authorization-server
   curl -s http://8.140.36.87/.well-known/oauth-authorization-server
   ```

## 四、明文 HTTP 与 OAuth 的隐患

服务器是 `http://` 无 TLS：OAuth 登录时用户名密码会**明文走公网**，且 Cherry Studio/Claude Desktop 很可能**拒绝非 HTTPS 授权服务器**。二选一：

- 用现有 certbot/443 给 `/mcp` 配 HTTPS，`PUBLIC_URL` 改 `https://...`；
- 或**本地演示**（`127.0.0.1:8765`，无公网明文问题，答辩投屏最干净）。

## 五、演示流程（对齐答辩脚本六 C）

1. 客户端填 MCP URL → 首次连接弹出浏览器 → 用**可登录的演示账号**完成 OAuth 授权（不要在投屏中展示令牌）。
2. 确认客户端列出 **14 个创作者工具**（证明走的是标准 `tools/list`）。
3. `search_posts("咖啡")` → 记下一条 `post_id`；再 `get_post(1029)` 核对返回的作品 ID。
4. `create_post_draft`，标题用唯一值如「答辩MCP演示-20261113-01」→ 拿到 `post_id` → `list_my_posts` 确认草稿真实出现（或回 App「我的作品」核对）。
5. 可选：`upload_media`（本地图片）+ `update_post_draft` 修改并核对。
6. 明确确认后 `submit_post_for_review` → 状态 `PENDING` → 管理员在管理端审核 → 普通用户验证公开可见。
7. 展示审计日志（答辩加分点「每一步都有痕迹」）：

   ```bash
   tail -f /var/log/pixelflow/mcp-audit.jsonl   # 云端
   Get-Content tmp\mcp-audit.jsonl -Tail 20      # 本地
   ```

   审计行示例：`{"event":"mcp_tool","tool":"create_post_draft","account":"...","status":"ok",...}`。

## 六、验收判据

- 外部工具调用 → 同一业务系统里的**真实状态变化**（作品 ID、状态可核对）。
- 保留工具名、作品 ID、结果；不把内部 Python 函数调用称为外部 MCP 调用。
- 授权身份与客户端可见工具列表一致；投屏不含令牌、密码、审计日志里的敏感原文。
