# Android 帖子分享验收

## 范围

按组长最终口径：仅 PUBLISHED 作品可分享；独立 `assets/api.properties` 的 `web_url`，默认 `http://localhost:5173`；链接 `{web_url}/#/post/{postId}`，不从 API 地址推导。获取最新完整详情后展示面板，执行动作前再次复核。

卡片宽1080px、高不超过4096px，标题最多2行、正文最多12行并省略，含封面、头像作者、相对时间、点赞、后端评论总数、品牌与链接。时间 `publish_time ?? create_time`，不改其他页面展示。无图/封面失败/2秒超时使用渐变。

本期不实现二维码、pixelflow 深链；不改后端、Web、契约或迁移，不新增依赖，不要求公网部署。导出图片无法随撤回而撤销。

## 自动化复现

以下为Git Bash命令，设备serial按 `adb devices` 调整。默认runner排除 `ShareEvidence` 注解的显式环境专项，普通设备测试不依赖临时Java服务/固定作品/Photos。专项需要明确选择并运行，缺配置或版本不符会失败，不以Assume跳过冒充通过。

```bash

  -Pandroid.testInstrumentationRunnerArguments.class=com.PixelFlow.app.API.LegacyShareFlowTest \
  -Pandroid.testInstrumentationRunnerArguments.notAnnotation= --console=plain
```

## 真实HTTP与截图专项复现

必须使用独占、可丢弃的本机H2服务，不使用已有远程API配置。启动现有Java构建产物时显式设置下列环境，再启动服务；所有凭据通过本机环境注入，不入库：

```bash
export SERVER_ADDRESS=127.0.0.1 SERVER_PORT=18080
export DB_URL='jdbc:h2:mem:share_verify;MODE=MySQL;DATABASE_TO_LOWER=TRUE;DB_CLOSE_DELAY=-1'
export DB_USER=sa DB_PASSWORD='' PIXELFLOW_RATE_LIMIT_ENABLED=false
export PIXELFLOW_SEED=true
# 在本机设置 PIXELFLOW_JWT_SECRET、PIXELFLOW_ADMIN_PASSWORD
java -jar server/target/pixelflow-server-0.1.0.jar
```

另开终端：在该独立服务通过现有注册接口创建测试作者。设置 `SHARE_AUTHOR_TOKEN` 或 `SHARE_AUTHOR_USERNAME/SHARE_AUTHOR_PASSWORD`，以及 `SHARE_ADMIN_TOKEN` 或 `SHARE_ADMIN_USERNAME/SHARE_ADMIN_PASSWORD`。脚本只接受loopback、禁用代理和重定向、需要显式声明独立H2，输出动态postId而非固定49：

```bash
python docs/testing/share/create_local_fixture.py --base-url http://127.0.0.1:18080 --isolated-h2
adb -s emulator-5554 reverse tcp:18080 tcp:18080
# sharePostId 使用脚本本次输出的值；本次实际为1
adb -s emulator-5554 shell am instrument -w \
  -e class com.PixelFlow.app.API.PostShareEvidenceTest \
  -e annotation com.PixelFlow.app.share.ShareEvidence \
  -e shareApiUrl http://127.0.0.1:18080/ -e sharePostId 1 \
  com.PixelFlow.app.test/androidx.test.runner.AndroidJUnitRunner
```

必须先安装以上构建产物中的应用和测试APK。截图专项还要求API37的系统IntentResolver与Google Photos、英文分享目标。若用Gradle运行，需同时覆盖默认 `notAnnotation` 为空并指定同一class与参数，不能只选择annotation而把API28专项一起运行。

本次输出 `share_post_clipboard=http://localhost:5173/#/post/1`，见 `local-post-clipboard.txt`；独立18080内存服务验收后已停止。Web另在 `web-app` 执行 `npm run dev`，其现有代理默认8080；需让独立Java服务监听8080或用显式本地端口转发，禁止误连共享服务。此前已将Android实际复制的 `http://localhost:5173/#/post/49` 在宿主浏览器打开，看到对应标题、作者和正文，保留 `post49-clipboard.txt` 作为历史证据；它不再是测试前置条件。模拟器localhost指自身，复制文本在宿主机验证；对外使用前需配置真实可达Web地址。

停止本次独立Java/Vite进程并移除相应adb reverse即可结束联调，H2内存库随进程销毁。隔离自动化恢复ApiClient单例，清理本次相册图片，不清理其他用户文件。

## 失败记录与纠正

- 既有收藏详情回归首次8通过1失败，原因是API37 Espresso调用不存在的InputManager方法。最小替换该用例点击/返回方式，保留业务断言，最终9项通过。
- API28新增测试前两轮均2失败：首轮非法字符串作品ID且撤权使进程退出；次轮没有操作权限对话框。修正为数字ID和真实系统允许/拒绝按钮，最终2项通过，没有跳过。
- API37专项首次误选API28类导致2项版本断言失败，之后精确选择相应class通过。
- 此前称普通FileProvider不支持删除文件的判断不正确：AndroidX Core1.9.0实现了delete；本轮通过真实URI验证删除，无需据此修改生产逻辑。
