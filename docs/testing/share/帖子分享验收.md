# Android 帖子分享验收

## 范围与口径

按组长确认实现：仅 `PUBLISHED` 可分享，链接采用 `{web_url}/#/post/{postId}`。`web_url` 独立配置于 `app/src/main/assets/api.properties`，本地默认 `http://localhost:5173`，不从 API 地址推导。宿主机浏览器负责验证本地链接；模拟器中的 localhost 指模拟器自身。

分享卡片宽 1080px、高度不超过 4096px，标题最多 2 行、正文最多 12 行并省略；包含封面、作者、时间、点赞、后端评论总数、品牌及链接。时间使用 `publish_time ?? create_time`，不改变其他页面展示。

本期不实现二维码和 `pixelflow://` 深链；不修改 Web、后端接口、契约和数据库，不要求公网部署。已导出图片无法随作品撤回而撤销。

## 本地环境

- 日期：2026-11-06。
- 开发基线：`dev` 的 `c00402f`，功能分支 `feature/post-share`。
- Windows；本地可用 Android AVD：`Medium_Phone_API_37.0`，设备 API 37。
- 本机仅安装 API 37 系统镜像，尚无 API 28 模拟器；API 24–28 存储权限与 FileProvider 设备验收待补，不以 API 37 结果代替。
- 独立 Java 服务：仅监听本机 8080，H2 内存库 `postshare`，演示数据启用，Redis 限流关闭，不连接生产或共享数据库；本次启动运行时 Java 21.0.11。
- Web：现有 Vite 服务 `http://localhost:5173`，代理到本机 Java。没有修改 Web 代码。
- Android 原 API 配置仍指向既有远程地址；自动化必须注入本地 MockWebServer，禁止向该远程地址写入验收数据。

## 复现命令

```bash
./gradlew :app:assembleDebug :app:testDebugUnitTest --console=plain
./gradlew :app:connectedDebugAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.class=com.PixelFlow.app.API.PostShareFlowTest,com.PixelFlow.app.share.ShareImageJobTest \
  --console=plain
```

本地链接验收：启动独立 Java 测试服务后，在 `web-app` 执行 `npm run dev`，Android 复制分享链接，再在宿主机浏览器粘贴打开。不要将模拟器的 localhost 当成宿主机；此默认地址用于宿主机浏览器验收，实际对外分享前需配置可访问的 Web 地址。

测试夹具通过反射替换 `ApiClient` 单例使用 MockWebServer，结束恢复原实例并清理本次创建的相册条目。它能验证客户端状态和存储行为，但不代替真实 Java 公开状态鉴权测试。

## 发现的既有边界

现有 `PostService.transition()` 在无媒体时拒绝提交审核（409 `INCOMPLETE_DRAFT`），因此正常 HTTP 发布链路无法创建纯文字 PUBLISHED 夹具。本任务不修改后端规则；纯文字分享通过 Android 隔离响应验证，不能宣称已经完成真实后端无图发布。此限制不应通过扩大任务范围或修改后端状态机解决。

既有 FavoriteDetailReviewTest 首轮有1项因 API37 的 Espresso InputManager API兼容问题失败；现仅将该用例的点击与返回替换为实际Activity主线程操作，保留全部业务断言，最终9项全部通过，无跳过、无依赖升级。
