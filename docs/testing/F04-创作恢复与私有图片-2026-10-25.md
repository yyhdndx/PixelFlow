# F04 创作恢复与私有图片

日期：2026-10-25。本轮推进 Android 创作流程，不接管 Java Issue 11 或 Python Issue 12；保留主目录此前所有未提交改动。

2026-10-26 增量：Java 任务 11（幂等创建）已合入远程 master 后，客户端放开“创建结果未知”的保守阻塞，重试复用
同一 `Idempotency-Key` 恢复同一草稿，不再要求先到“我的作品”核对。设备用例由“阻塞”改写为“同键重试恢复”，
MockWebServer 模拟同键重放返回 200。本地 59 项 JVM、37 项设备测试、Lint 0 错误/282 警告通过；真实云端与真机联调仍未验收。

## 改动与行为

- 创作流水线迁到 `DraftEditorModel`，通过 ViewModel 保留页面重建期间的同一次操作。图片压缩在后台执行，网络阶段顺序推进；上传成功立即保存媒体 ID，创建成功立即保存草稿 ID，提交审核失败后复用它们。
- 标题、正文、媒体 URI/ID、创建请求键和阶段写入恢复记录。写创建请求前同步保存“结果未知”标记，读取时以最新记录覆盖可能较旧的 Activity 状态；记录不保存令牌，并排除云备份和设备迁移。图片选择改为 `ACTION_OPEN_DOCUMENT`，尝试保留读取授权；授权失效时提示重新选择，不伪造上传成功。
- 已知 ID 的保存/提交失败先读取作品状态。已是 PENDING/PUBLISHED 时确认完成；仍为草稿时允许用户重试；核对失败只开放读取重试。内容未变化时跳过重复保存。编辑框、图片删除和提交按钮在写入期间禁用，各返回入口统一处理未保存内容。
- 创建响应未知且没有作品 ID 时，客户端生成并持久保存稳定 `Idempotency-Key`。后端（Issue 11）合入后，
  允许以同一键直接重试保存/提交，复用已上传媒体和草稿 ID 恢复同一作品；不再要求先到“我的作品”核对。
  编辑内容仍保留，但未知创建期间内容字段保持禁用，避免改动内容导致同键冲突。
- 草稿列表及编辑预览通过 `AccountMedia` 读取私有图片。只对配置的同协议/主机/端口、严格匹配 `/api/media/{id}/content` 的地址附带令牌；401 使用既有串行刷新流程，拒绝认证请求重定向。第三方图片不附加认证。
- 私有图片禁用 Glide 内存/磁盘缓存，账号/绑定变更丢弃旧结果；界面清理使用可在 Activity 销毁期间工作的方式，避免首次专项发现的图片清理崩溃。账号失效/变化停止后续创作阶段并关闭旧编辑页。

新增 JVM 专项 `CreationMediaClientTest`：真实二进制读取、认证刷新、拒绝异源/非媒体地址、禁止重定向携带认证、游客不发请求，以及创建请求头和原始请求体兼容。

新增设备专项 `CreateWorkFlowTest`：

1. 提交审核失败再试，不重复上传、创建或保存未变内容。
2. 第二张图片上传失败，保留第一张媒体 ID 和编辑文字；重建后复用。
3. 创建请求进行中重建，保持一条流水线并禁止再次点击。
4. 创建已提交但响应报错，重建及新 ViewModel 从较旧快照恢复都不重复创建。
5. 审核提交已成功但响应报错，回读 PENDING 后结束，不重复提交。
6. 状态核对失败，只允许读取重试，不发出新的修改。
7. 创建中退出账号，不在新会话继续提交审核。
8. 保存后重新打开，读取私有图片，修改原作品再提交审核。
9. 同一图片 URL 在两个账号下返回不同颜色，实际显示切换后的颜色且重新发起认证请求，排除缓存复用。

设备使用 Pixel_2_API_36 / Android 16，HTTP 使用设备内 MockWebServer。颜色测试验证实际显示的像素，不只检查是否发送请求。恢复测试建立新的 ViewModel 并从持久记录恢复，不将其描述为已经完成系统杀进程/真机测试。
