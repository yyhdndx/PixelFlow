# Android F01 / F02 实施与验收

日期：2026-10-24。对应 [下一阶段任务](../工作区审查与下一阶段任务-2026-10-24.md) 的第一次实施批次。

## 改动范围

本次在主工作区已有的 Android 页面基础上修复 F01、F02。业务源码改动限定为 `CommunityClient`、新增 `MyPostsPage` / `AccountDataActivity`、六个账号相关页面和三个列表适配器；没有修改后端接口、数据库或云端配置。保留原有未提交改动，尚未提交或推送。

### F01：本人作品接口与分页

- `GET /api/posts` 按真实的作品数组解析，不再套用 Feed 的 `ApiResponse`。客户端的 `MyPostsPage` 只保存本地分页状态，不虚构服务端字段。
- 以末项作品 ID 续页；短页仍可继续查询，空数组才表示结束。草稿、待审、已发布、驳回、撤回状态均保留。
- 校验分页参数、正整数 ID 及其范围、状态、数组完整性和严格递减顺序。重复边界、重复行、乱序页按异常处理，保留已加载列表并提供刷新重试，避免重复追加和无限翻页。

### F02：页面恢复与写入核对

覆盖关注/粉丝列表、收藏、本人作品、历史画像、用户主页、推荐偏好六个页面。

- 页面停止时取消读请求、使旧回调失效、复位加载状态并清空旧数据；返回时重新读取首页。此批次采用首页刷新，不保留此前滚动位置。
- 回调还需匹配当前会话；账号已变化时重新初始化页面，旧结果不用于新账号界面。
- 发布/撤回、取消收藏、关注/取消关注和偏好写入不随页面停止而取消。利用现有客户端串行队列，让返回后的读取排在写入之后；旧页面回调不再修改界面。
- 写入期间禁止重复操作。无论写入成功还是响应失败，都重新读取服务器状态，读取成功后才恢复操作按钮；核对失败时提供重试，不把网络失败直接当作服务器回滚。
- `ConnectionAdapter` 只展示数据并上报用户动作，写请求归页面统一处理。列表翻页安排在当前布局回调之后执行，避免在 RecyclerView 计算布局时修改适配器。

新增 7 项 `CommunityClientTest` 用例覆盖空数组、五种作品状态、短页继续与空页结束、重复边界/乱序、非法响应、分页参数、认证刷新及服务器失败。

新增 `AccountPagesFlowTest` 的 6 个测试方法覆盖 29 个页面/操作组合：

| 场景 | 覆盖范围 |
| --- | --- |
| 读取中停止后返回 | 六个页面；延迟的旧响应不覆盖新读取结果 |
| 从其他页面返回 | 六个页面；服务端数据更新后重读 |
| 切换账号 | 六个页面；旧账号列表清空、旧内容不可见、新账号数据正确 |
| 写入期间重建页面 | 本人作品、收藏、关系、用户主页、偏好；只发一次写请求并核对结果 |
| 服务端已写入但返回错误 | 上述五类写操作；读取已提交状态，不自动重复写入 |
| 核对读取也失败 | 用户主页；按钮保持禁用，重试确认后可再次操作 |

原有 `ProfileFlowTest` 的退出登录用例同步使用工作区现有的直接退出入口；没有恢复已移除的旧账号按钮。

首次设备验证前遇到两项测试环境问题：旧测试引用已删除的 `btn_account`，已更新；模拟器快照启动后应用安装失败，冷启动后正常。首轮设备用例有一处断言将 RecyclerView 的隐藏缓存视图误算作可见内容；修正为检查可见内容，同时明确断言列表数据已清空，并重新运行。
