# 画像历史偏好真实链路验收

对应 Gitee issue 12《验证真实画像同步、历史分页与偏好链路，交付可复现演示样例》。本文记录真实
Java → Python → MySQL 链路的本地验证方式与结果，用于区分三件事：**代码已实现**、**本地验证
成功**、**云端是否实际启用**。本次不重写历史接口、周期调度器或偏好存储，也不修改共享认证逻辑。

## 1. 结论

- 两个账号的真实行为事件经 Java 业务接口写入 MySQL，由 Python 包装器同步、生成画像快照，可读出
  当前画像与历史版本；Java 代理与 Python 本人接口结果一致。
- `scheduled_maintenance` 包装器在本机真实跑通一次完整维护；用单页上限制造一次有界中断后，下一次
  运行从已提交游标继续并完成，空同步不重复计分。
- 偏好全部由 Java 写入，Python 预览只读；作品排除、作者屏蔽、主题抑制、个性化开关的语义与契约
  一致，历史快照不被改写。
- 服务不可用、分析库错误、无数据三者可区分：错误返回 503/401，不会伪装成 200 空数组。
- 云端定时器、Android 真机、Java 17 目标运行时与 Python 3.11 目标版本**本次未验证**，见第 8 节。

## 3. 隔离数据库与账号

脚本只接受回环地址，并自行创建两个带随机后缀、以 `_test` 结尾的库：

- `pf_issue12_java_<8位十六进制>_test`：Java 业务库，启动时由 Flyway 建表；
- `pf_issue12_analytics_<8位十六进制>_test`：Python 分析库，启动时由 `mysql_schema` 建表。

运行结束后删除这两个库（`--keep-databases` 可保留排查），不触碰其他库，也不清理不属于本次运行
的数据。测试账号需要能创建 `pf_issue12_%` 库：

```sql
CREATE USER 'pf_test'@'localhost' IDENTIFIED BY '<本地测试密码>';
GRANT CREATE ON *.* TO 'pf_test'@'localhost';
GRANT ALL PRIVILEGES ON `pf\_issue12\_%`.* TO 'pf_test'@'localhost';
```

首次准备独立实例（不修改已安装的 MySQL 服务）：

```powershell
$root = 'G:\project\2026\pixel-flow\server\target\issue12-mysql'
& 'C:\Program Files\MySQL\MySQL Server 8.4\bin\mysqld.exe' --initialize-insecure `
    --basedir='C:\Program Files\MySQL\MySQL Server 8.4' --datadir="$root\data"
# my.ini 中设置 datadir、port=3307、bind-address=127.0.0.1、mysqlx=0
& 'C:\Program Files\MySQL\MySQL Server 8.4\bin\mysqld.exe' --defaults-file="$root\my.ini"
```

## 4. 一条命令复跑

```powershell
cd G:\project\2026\pixel-flow\server
mvn -DskipTests package

cd G:\project\2026\pixel-flow
intelligence\.venv\Scripts\python.exe intelligence\scripts\verify_profile_pipeline.py `
    --mysql-port 3307 --mysql-user pf_test --mysql-password <本地测试密码>
```

也可以改用 `MYSQL_TEST_USER` / `MYSQL_TEST_PASSWORD` / `MYSQL_TEST_PORT` 环境变量。脚本按顺序
启动两端（端口随机、避免占用 8080/8001），等待 `/health`，随后执行 7 个阶段的 56 项断言，退出码
0 表示全部通过；产物写入 `server/target/issue12-verify-<run_id>/`：

- `summary.json`：环境、库名、脱敏账号、每条断言与耗时；
- `java.log`、`python.log`：两端日志，失败时摘要内附尾部。

失败时退出码为 1 并打印首个未通过断言与堆栈；`PASS:` 行给出断言数量与摘要路径。

## 5. 断言覆盖

| 阶段 | 覆盖内容 |
| --- | --- |
| `env` | 真实 MySQL 8.4 + 7 条 Flyway 迁移；种子公开作品可用于真实事件；只创建本次命名的库 |
| `cold_start` | 新用户 version=0 冷启动、历史为空；伪造 `user_id` 不能切换身份；缺失/无效令牌与运维密钥被 401 拒绝；分析库初始无事件 |
| `maintenance` | 真实点击/停留/服务端点赞；重复 `eventId` 判重；包装器退出码 0、状态目录 `last_status=complete`、锁文件存在；版本 1 与主题分数按规则生成 |
| `resume` | `--max-sync-pages 1` 产生 `incomplete` 与退出码 2，游标停在已提交页（57）；下一次运行补齐剩余 5 条并完成；空同步导入 0、版本不变；`/internal/sync` 幂等且游标单调 |
| `history` | `count=1` 从 v3 逐页读到 v1、降序不重复、末页结束；字段白名单；Java 代理与 Python 逐项一致；两账号隔离；非法/重复分页 400（Python 422）；读取不生成版本；新增 v4 后旧游标页仍返回 v2 |
| `preferences` | 默认偏好；预览 `personalized` 与 `profile_version=4`；作品排除、作者屏蔽、主题抑制逐项生效且版本递增；主题抑制把个性化主题分归零但推荐仍返回；历史快照保留生成时的主题；个性化关闭降级为 `popular`/`personalization_disabled` 且不删画像；撤销后恢复；Python 写端点 410 |
| `failures` | 刷新轮换后旧会话在两端均 401；Python 停止时 Java 当前画像与历史代理 503（历史错误仍带 `Cache-Control: no-store`）；Python 恢复后可读；删除分析库后 Python 与 Java 均 503；Java 停止后 Python 身份校验 503 |

`502 INVALID_ANALYTICS_RESPONSE`（上游结构/身份不符、分页矛盾）与超时上界由
`ProfileHistoryGatewayTest` 的两个用例覆盖，端到端脚本不构造畸形上游。

## 7. 两账号演示步骤

1. 启动 Java（`PIXELFLOW_SEED=true`，真实 MySQL 库）与 Python（`ANALYTICS_DB` 指向真实分析库），
   确认 `/health`；注意种子是 `ApplicationRunner`，`/health` 正常不等于种子写完。
2. 注册 A、B 两个账号，分别登录。读取 A 的 `GET /api/users/me/profile`：`version=0`、
   `cold_start=true`、`topics=[]`；`GET /api/users/me/profile/history?count=1`：`items=[]`、
   `next_cursor=null`。这一步是“无数据”，与第 8 步的 503 不同。
3. A 对美食类作品发 `CLICK`、`DWELL`（带 `durationMs`），再 `PUT /api/interactions/likes`
   产生服务端点赞；B 对宠物类作品做同样操作。
4. 运行一次包装器（见 `intelligence/README.md`）：A、B 各生成 version=1，A 主题首位为“美食”、
   B 为“宠物”，`event_counts` 为 `{"CLICK":2,"DWELL":1,"LIKE":1}`。
5. 再产生两批事件并各运行一次维护，A 得到 v2、v3；`count=1` 逐页读到 v1，末页
   `has_more=false`。
6. `PUT /api/recommendations/me/preferences {"personalized":false}` 后读取
   `GET /recommendations/me/preview`（Python 端口，仅本机联调）：`reason=personalization_disabled`、
   `strategy=popular`、`profile_version=0`；恢复为 true 后主题分重新参与。
7. 对某作品 `PUT /api/interactions/not-interested`、对某作者
   `PUT /api/recommendations/me/blocked-authors/{id}`、对主题
   `PUT /api/users/me/profile/topics/美食 {"suppressed":true}`：预览中作品消失、作者作品消失、
   `components.topic` 归零；重新读取历史，v3 仍保留“美食”。
8. 停掉 Python 后请求 `GET /api/users/me/profile`：503 `ANALYTICS_UNAVAILABLE`；恢复 Python。
   删除分析库后再次请求：Python 与 Java 均为 503，而不是 200 空画像。

示例响应（字段裁剪，值为脱敏示意）：

```json
{"user_id":"<8位脱敏>…","version":3,"rule_version":"profile-rules-v1",
 "cold_start":false,"topics":[{"name":"美食","score":6.0,"share":1.0}],
 "event_counts":{"CLICK":2,"DWELL":1,"LIKE":1}}
```

```json
{"user_id":"<8位脱敏>…","items":[{"version":3,"cold_start":false,
 "topics":[{"name":"美食","score":6.0,"share":1.0}]}],"has_more":true,"next_cursor":"3"}
```

## 8. 限制与未验证项

- **云端是否启用定时器未核对**：仓库提供包装器与 systemd 模板，本地只证明“能跑、能续跑”，
  不代表云端 timer 已安装或最近成功过。
- **目标运行时未复跑**：本次 Java 24 运行、JDK 21 编译（release 17）、Python 3.13；团队标准的
  Java 17 + Python 3.11 组合需在对应机器再跑一次脚本。
- **Android 未进真机链路**：验证的是 App 会走到的 Java HTTP 入口；历史页面仍以 MockWebServer
  自测，真机联调是后续独立工作。
- **账号停用/过期未在端到端覆盖**：刷新轮换导致的会话失效已验证；停用需管理员权限，由
  `UserProfileHttpTest` 等单测覆盖。
- **502 与超时**：由 Java 网关单测覆盖，端到端未伪造畸形上游。
- 本任务不改变推荐正式交付入口、Agent/MCP 与 Android 推荐流，不能以本次联调宣称这些已完成。
