# issue 13：创作审核真实链路验收

## 基线与范围

- 基线：`787f0d8089ee82e6b142e579557514676836c8c4`（`origin/master`）。
- 分支：`feature/issue-13-creation-lifecycle-verify`。本记录随测试提交，最终提交号以 PR 为准。
- 环境：Windows、Java 17.0.12、Maven 3.10.0、MySQL 8.4.13，服务仅监听 `127.0.0.1`，HTTP 端口随机分配。
- 新增 `PostLifecycleHttpTest` 和 `MySqlPostLifecycleHttpTest`，复用现有创建幂等、上传、审核、认证及媒体权限实现。未修改生产接口、Android、Python、工作流或数据库迁移。

测试使用 Java HttpClient 访问真实 Tomcat。A/B 经注册和登录接口创建；管理员由本次启动参数初始化，再经登录接口取得令牌。密码及 JWT 密钥随机生成，只用于测试进程。图片由 ImageIO 在内存生成，不访问外部素材站点。

数据库读取仅核对迁移、作品数、幂等记录、媒体关联和保留的收藏关系；所有业务状态变化均经 HTTP。结束时按本次账号和作品清理关联，再删除账号，保留迁移表；场景断言失败也执行 finally 清理。MySQL 专项拒绝非本机、非 `_test` 后缀、与其他专项共库或已有管理员的数据库，并检查服务器版本为 8.4。

## 可重复执行

先由本地数据库管理员创建本专项独占库，不使用日常业务库或云端共享库：

```sql
CREATE DATABASE pf_post_lifecycle_test
  CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_bin;
```

在仓库根目录的 PowerShell 中执行；数据库账号须对该测试库拥有建表和读写权限。替换 JDK 路径及本地测试账号，密码交互输入，不写入文件：

```powershell
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-17'
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
$env:MYSQL_TEST_POST_LIFECYCLE_URL = 'jdbc:mysql://127.0.0.1:3306/pf_post_lifecycle_test?connectionTimeZone=UTC&tinyInt1isBit=true&allowPublicKeyRetrieval=true&sslMode=DISABLED'
$env:MYSQL_TEST_USER = Read-Host '本地测试数据库账号'
$secret = Read-Host '本地测试数据库密码' -AsSecureString
$env:MYSQL_TEST_PASSWORD = [System.Net.NetworkCredential]::new('', $secret).Password
mvn -f server/pom.xml -B -Dtest=PostLifecycleHttpTest,MySqlPostLifecycleHttpTest test
# 再执行同一命令，验证同一专属库可重复运行。
mvn -f server/pom.xml -B -Dtest=PostLifecycleHttpTest,MySqlPostLifecycleHttpTest test
Remove-Item Env:MYSQL_TEST_PASSWORD
```

每个类各有一个完整场景测试，包含两个作品的生命周期。未配置 MySQL 变量时该专项会跳过，不能算作验收通过。报告以 Surefire 的实际测试数量计数，不把 HTTP 请求数计作测试数。

全量回归命令为 `mvn -f server/pom.xml -B clean verify`。要运行全部 MySQL 测试，还需按已有上手指南为以下变量提供各自独立的本机 `_test` 库，不能指向本生命周期库：`MYSQL_TEST_URL`、`MYSQL_TEST_CONNECTIONS_URL`、`MYSQL_TEST_FAVORITES_URL`、`MYSQL_TEST_POST_IDEMPOTENCY_URL`、`MYSQL_TEST_POST_IDEMPOTENCY_RESTART_URL`、`MYSQL_TEST_MIGRATION_URL`、`MYSQL_TEST_MIGRATION_V7_URL`、`MYSQL_TEST_PREFERENCES_URL`、`MYSQL_TEST_PUBLIC_PROFILE_URL`、`MYSQL_TEST_STATS_URL`、`MYSQL_TEST_USER_POSTS_URL`。迁移导入测试使用全新空库；既有重启专项会清理其专属库。

迁移仍为 V1–V7、V9。本次在全新隔离库按现有 Flyway 规则执行并核对成功版本；不增加 V8 占位、不启用 out-of-order、不执行 repair。这不构成对已部署库跳过真实头像 V8 的部署建议。

CI 的 `MYSQL_TEST_POST_LIFECYCLE_URL` 及独立库由任务 14 统一接入 `.github/workflows/backend.yml`，本任务不编辑该文件。

## 实际结果

2026-10-26 本地执行：

| 执行 | 运行数 | 失败 | 错误 | 跳过 |
| --- | ---: | ---: | ---: | ---: |
| H2 生命周期专项 | 1 | 0 | 0 | 0 |
| H2 + MySQL 8.4 生命周期专项 | 2 | 0 | 0 | 0 |
| `clean verify` 全量回归（全部 MySQL 专项启用，包含再次运行生命周期专项） | 226 | 0 | 0 | 0 |

全量构建为 BUILD SUCCESS，用时 3 分 8 秒；生命周期 MySQL 专项在同一 `pf_post_lifecycle_test` 库第二次执行通过，H2 使用新的随机内存库。只读核对该 MySQL 库中 users、posts、media、post_media、post_creation_idempotency、moderation_records 均为 0，迁移历史保留。旧 Feed、作品、收藏、关注、资料及幂等/重启测试均纳入本次完整回归。

脱敏链路结果（ID、账号、令牌均为每次动态生成）：

| 步骤 | HTTP / 结果 |
| --- | --- |
| 上传 PNG、JPEG | 201；返回媒体 ID，JPEG 规范化为 PNG |
| 首次带 UUID 创建，丢弃响应体 | 201 |
| 原键、原 Draft 重试 | 200；恢复同一 `post_id`；数据库仅一条作品、一条幂等记录及按顺序的两条媒体关联 |
| 重读、编辑 | 200；编辑后原创建请求重放返回当前内容 |
| 提交及重复提交 | 200 / PENDING；不会直接公开 |
| 管理员批准及重复批准 | 200 / PUBLISHED；审核记录仍一条 |
| B 点赞、收藏 | 200；公开详情、Feed、作者作品页的本人点赞为 true，A 为 false；收藏卡片为已收藏 |
| A 撤回 | 200 / WITHDRAWN；本人列表保留原 ID；公开列表和 B 收藏页不再展示 |
| B / 游客重读旧详情与媒体 URL | 404 / POST_NOT_FOUND 或 MEDIA_NOT_FOUND |
| 第二份草稿驳回、修改、重提、批准 | PENDING → REJECTED → DRAFT → PENDING → PUBLISHED；审核记录正好两条，记录前后状态和理由 |

DRAFT、PENDING、REJECTED、WITHDRAWN 状态下检查 A 可读图片、B/游客不可读；PUBLISHED 时均可读。读取的是图片实际字节，核对 PNG 类型、尺寸和禁止缓存。每份草稿使用独立媒体，不被另一篇公开作品引用。测试根据上传响应 URL 保留原路径，向本次随机端口请求；固定 public-base-url 不作为测试监听端口。

B 编辑、提交、撤回及普通账号访问审核接口均为 403；匿名和无效令牌修改作品为 401；失败后重读状态不变。PENDING/PUBLISHED 编辑、已发布作品再次提交、非法审核流转均按现有 409 INVALID_STATE 断言。创建重放在编辑、提交、公开、撤回后均保留原 ID 和当前状态。

## A / B / 管理员演示顺序

手动演示使用另一个本机独占 `_test` 库，例如 `pf_post_lifecycle_demo_test`；不要与自动化测试并行共库。按后端上手指南注入 `DB_URL`、`DB_USER`、`DB_PASSWORD`，`SERVER_ADDRESS=127.0.0.1`、`PIXELFLOW_SEED=false`、`PIXELFLOW_PUBLIC_BASE_URL=http://127.0.0.1:8080`。启动前仅在当前终端注入随机 `PIXELFLOW_ADMIN_PASSWORD` 和 `PIXELFLOW_JWT_SECRET`，管理员通过已有启动机制创建，不将凭据存入仓库或公开管理端口。

```powershell
mvn -f server/pom.xml -B package
java -jar server/target/pixelflow-server-0.1.0.jar
```

另开本地终端调用；所有 Authorization 均为 `Bearer <相应登录返回的 accessToken>`。注册使用每次唯一的 username 和本地私有密码，管理员 username 为 `admin`。以下请求体均为 JSON，上传除外：

| 顺序 / 身份 | 接口、请求与预期 |
| --- | --- |
| 1 / A、B | `POST /api/auth/register`，`{"username":"<唯一账号>","password":"<本次密码>","nickname":"作者甲或访问者乙"}` → 201；各自 `POST /api/auth/login` → 200 |
| 2 / 管理员 | `POST /api/auth/login`，使用本次启动初始化的管理员密码 → 200；保存三份独立 token |
| 3 / A | `POST /api/media`，multipart 的 file 上传本地 JPEG/PNG → 201；保存 mediaId 与 URL |
| 4 / A | `POST /api/posts`，请求头 `Idempotency-Key: <本次 UUID>`，体 `{"title":"演示","content":"中文正文","mediaIds":["<mediaId>"]}` → 201；忽略首次响应体，以原键原体重试 → 200，得到原 post_id |
| 5 / A、B、游客 | `GET /api/posts/<id>`，A 为 DRAFT，B/游客 404；图片 URL 同样 A 为 200、B/游客 404；A `GET /api/posts` 可见原 ID |
| 6 / A | `PUT /api/posts/<id>`，完整 Draft（含原 mediaIds）修改标题正文 → 200；GET 重读；原键原始创建体重试仍是原 ID 和当前内容 |
| 7 / A | `POST /api/posts/<id>/publish` → 200 / PENDING；重复提交仍 PENDING；B/游客图片仍 404 |
| 8 / B | 尝试 PUT、publish、withdraw → 403；A/B 调管理审核接口 → 403；A 重读状态仍 PENDING |
| 9 / 管理员 | `POST /api/admin/posts/<id>/moderation`，`{"status":"PUBLISHED","reason":"本地验收通过"}` → 200；重复批准仍 200；`GET /api/admin/moderation?count=50` 仅一条对应记录 |
| 10 / A、B | `GET /feed/?count=50&accept_video_clip=true`、`GET /api/users/<A真实ID>/posts?count=50` 和作品详情均包含该作品；A ID 由 `GET /api/users/me` 获得；图片公开可读 |
| 11 / B | `PUT /api/interactions/likes` 和 `/api/interactions/favorites`，`{"targetId":"<id>","active":true}` → 200；详情、作者页 is_liked=true；`GET /api/users/me/favorites?count=50` 可见完整卡片 |
| 12 / A | `POST /api/posts/<id>/withdraw` → 200 / WITHDRAWN；A 本人列表保留原 ID，公开 Feed/作者页及 B 收藏页消失；B/游客原详情和旧图片 URL 404 |
| 13 / A、管理员 | 另上传一张图并用新 UUID 创建第二份草稿，提交；管理员以 `status=REJECTED` 驳回，重复审核不增记录；A 修改后为 DRAFT，重提后 PENDING，管理员批准为 PUBLISHED；审核记录恰有 PENDING→REJECTED、PENDING→PUBLISHED 两条 |

可用 curl 模拟丢弃首次创建响应，成功后第二次使用完全相同的键和文件内容：

```bash
curl -sS -o /dev/null -w '%{http_code}\n' -X POST "$BASE/api/posts" \
  -H "Authorization: Bearer $A_TOKEN" -H "Idempotency-Key: $KEY" \
  -H 'Content-Type: application/json' --data-binary @draft.json
curl -sS -X POST "$BASE/api/posts" \
  -H "Authorization: Bearer $A_TOKEN" -H "Idempotency-Key: $KEY" \
  -H 'Content-Type: application/json' --data-binary @draft.json
```

`draft.json` 只保存本次媒体 ID 和业务内容，不包含凭据；不要生成新键来重试原创建。收到 ID 后编辑和提交使用作品接口。手动演示账号和作品由演示者负责清理；自动化测试只清理其自身资源。

## 验收边界

上述结果为后端真实 HTTP 自动化验证；不代表 Android 真机、进程恢复或页面交互已经验收。Android 的上传媒体复用、编辑状态恢复、私有图片认证和 F04 关闭仍需 Android 侧独立记录。本任务不发布云端、不合并头像或本地 Android 改动。
