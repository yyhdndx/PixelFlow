## 字段与迁移

三个字段为 nullable BIGINT / JSON integer 或 null，单位 Unix 秒：

| 字段 | 写入时机 | 不更新时间的情况 |
| --- | --- | --- |
| create_time | 创建草稿 | 后续所有状态变化 |
| submit_time | DRAFT/REJECTED/WITHDRAWN 实际进入 PENDING | PENDING 重复提交、编辑、撤回、创建重放 |
| review_time | PENDING 审核通过或驳回 | 重复审核、管理员撤回 |
| publish_time | PENDING 审核通过 | 驳回、撤回、编辑、重复审核 |

迁移仅对当时 PUBLISHED 作品回填 publish_time=create_time；历史 submit_time/review_time 为 null，其他状态 publish_time 为 null。不能据此重建过去的提交/审核历史。

create_time 保持原含义。公开展示使用 `publish_time ?? create_time`（SQL 等价 `COALESCE(publish_time,create_time)`）；不改 Feed 的 ID 倒序和游标。审核队列的 submit_time 为 null 时显示“—”，不得用 create_time 冒充。

## 管理端接线示例与演示顺序

以下为字段示意，不含真实凭据，时间值仅用于解释格式：

```json
{"post_id":"123","create_time":1793580000,"submit_time":1793580300,"review_time":null,"publish_time":null,"status":"PENDING"}
```

1. 作者登录，创建草稿：`POST /api/posts`，三个时间字段均 null。
2. 作者提交：`POST /api/posts/{id}/publish`；管理员用 `GET /api/admin/posts?status=PENDING` 读取 submit_time。
3. 管理端时间转换用 `new Date(submit_time * 1000)`；等待秒数 `Math.max(0, Math.floor(Date.now()/1000)-submit_time)`；null 显示“—”。
4. 管理员驳回：`POST /api/admin/posts/{id}/moderation`，body 为 `{"status":"REJECTED","reason":"请修改内容"}`。详情中 review_time 有值、publish_time 仍 null。
5. 作者修改并重新提交，submit_time 更新；管理员通过同一审核接口提交 `{"status":"PUBLISHED","reason":"符合规范"}`，review_time 与 publish_time 使用相同时间。
6. `GET /feed/`、`GET /api/posts/{id}`、`GET /api/users/{作者ID}/posts`、收藏后 `GET /api/users/me/favorites` 均返回新字段。公开时间展示优先 publish_time。
7. 作者 `POST /api/posts/{id}/withdraw` 后本人详情保留所有时间；完整审核历史仍从 `GET /api/admin/moderation` 读取。

管理端实际显示提交时间与等待时长尚待协调方接线联调；本任务不宣称该页面验收已完成。
