# F06 持久登录与画像验收

日期：2026-10-26。本轮补齐 Android 侧 F06 的测试覆盖，并修正一处陈旧提示；不接管 Python 的“可解释画像样本”。保留主目录此前所有未提交改动。

F06 = 持久登录 + 画像/偏好验收。持久登录本体（`TokenStore` AES-GCM 加 Keystore + `ApiClient` 启动恢复）此前已实现但无测试；当前画像页 `InterestProfileActivity` 完全未被设备用例覆盖；历史画像分页缺客户端级校验。本轮逐一补齐，并修正登录页仍提示“重启后需再次登录”的矛盾文案。

## 改动与行为

- 新增 `TokenStoreTest`（androidTest，5 项）：保存/读取往返、缺省返回 null、退出清除、密文损坏时静默回退到未登录并清除脏条目、新建 `ApiClient` 从持久化会话恢复（模拟重启后的登录态恢复）。
- 新增 `ProfileInsightsFlowTest`（androidTest，6 项）：当前画像有话题/空态/失败重试/未登录提示，历史画像空态与失败态（空是正常态，失败才显示重试）。
- `CommunityClientTest` 新增 2 项历史画像分页单测：`before_version` 游标校验（`[1-9][0-9]{0,18}`）与 count 边界、响应解析与身份字段、二次分页游标传递。
- `profile_ui.xml`：`account_memory_hint` 由“应用重新启动后，需要再次登录。”改为“登录状态会保留在本机，重启应用无需再次登录。”——与已实现的持久登录一致。
- 偏好不宣称即时改变普通 Feed：既有 `preferences_note`（“这些偏好会影响之后的新推荐，当前信息流不会立即变化。”）已满足该验收口径，无需代码改动。
