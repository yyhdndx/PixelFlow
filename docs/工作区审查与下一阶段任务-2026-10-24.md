## 本轮确认的问题

以下来自静态代码审查与当前接口实现对照，未声称已在设备逐项复现。优先级 P1 表示阻塞对应核心流程的交付。

1. **[P1] 本人作品响应解析错误。** `CommunityClient.java:418–427` 将 GET `/api/posts` 解析为 ApiResponse 对象，但 `server/.../PostController.java:22–25` 返回作品数组。即使服务器成功返回 `[]` 或正常作品，也无法按当前客户端模型解析。“我的作品”不能直接交付。应保留后端既有数组契约，客户端独立解析，并用末项 ID 续页、空页结束；不要虚构服务端 next_cursor/has_more。
2. **[P1] 页面离开后请求状态无法恢复。** `FavoritesActivity.java:66–69,129–133` 等页面仅首次 onResume 加载，而 onStop 取消请求；CommunityClient 会抑制取消后的回调，inFlight/actionJob 等状态不能依赖这些回调复位。请求中退后台再返回，可能一直显示加载、禁止翻页或禁止再次操作。同型代码见 ConnectionsActivity、MyWorksActivity、HistoryProfileActivity、UserProfileActivity、PreferencesActivity。需覆盖读请求恢复、写入结果核对、返回刷新及会话切换。
3. **[P1] 创建成功、提交审核失败后重试会新建作品。** `CreateWorkActivity.java:337–356` 上传后创建作品，再提交审核，却未把成功获得的作品 ID 和 mediaId 写回编辑状态。后一步失败再点击提交，会重复上传并重新 POST 创建。需把上传、保存草稿、提交审核分阶段记录；明确写入结果未知时先核对，避免盲重试。Activity 重建也需保存编辑状态和操作阶段。
4. **[P1] 私有草稿图片未携带认证。** `MyWorksAdapter.java:46`、`CreateWorkActivity.java:268` 用普通 Glide URL 读取已有图片；当前工程没有对应的 Glide 认证请求适配。后端 MediaService.content 要求非公开图片属于当前认证用户。草稿/待审图片不能依赖游客 URL。需要仅对本站媒体端点附带认证并隔离账号缓存，禁止向第三方图片地址附加用户令牌。
5. **[P1] 详情收藏状态没有读取依据。** `WorkDetailActivity.java:108,1236–1263` 的 favorited 从默认 false 开始，只由本页点击修改；PostItem/WorkItem 没有承接收藏状态。已收藏作品重新进入详情会显示未收藏，第一次点击仍发送添加收藏。需要读取服务端状态并同步列表返回结果；已有后端详情只有 is_liked，不能假设已返回 is_favorited。

其他待验证事项：TokenStore 已使用 Keystore/AES-GCM，但当前测试没有覆盖进程重启、密钥失效、存储失败与退出后恢复；创作媒体 URI/编辑状态恢复也缺专项测试。这些目前列为验收任务，不宣称存在已复现的数据泄漏。
