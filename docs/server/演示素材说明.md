## 本地使用

文件在 `server/src/main/resources/static/demo-assets/`，随 JAR 打包，经 `/demo-assets/{文件名}` 提供。视频支持 GET Range 分段请求和 HEAD；CREDITS.txt 和 catalog.json 公开可读。

catalog.json 包含下载 URL、来源、作者、许可、处理方式、实际尺寸、大小、时长和 SHA-256。已抽样查看照片/头像，并用 ffprobe 确认视频为 H.264。

启用 `PIXELFLOW_SEED=true`，空库按三个批次插入 6 个虚构账号和 33 条作品（26 条图片作品、7 条视频作品，复用三段短片）。community-assets-v1 插入首批 24 条，community-assets-v2 追加 6 条，包含图书馆、街角车轮、草莓、日落，以及早餐和猫咪两个三图作品，可用于检查详情页多图浏览。community-assets-v3 再追加多肉、键盘和校园篮球场 3 条作品。正文保留署名和演示提示；视频首片段为封面、次片段为 MP4，适配现有客户端取首片段作封面的方式。

V4 迁移增加头像和批次记录。各批次只执行一次，重启不重复插入；已有 v1 批次的库追加 v2、v3 共 9 条作品，已有 v1、v2 的库只追加 v3 的 3 条作品，不重写已有内容。旧版 24 条色块占位作品不删除、不覆盖，因此保留占位数据的演示库完成三个批次后可能共 57 条。用户原有账号和作品保持不变。

首次初始化前设置 PIXELFLOW_PUBLIC_BASE_URL 为客户端可达地址；模拟器使用 http://10.0.2.2:8080，真机使用电脑局域网地址。修改变量不自动重写已保存的 URL。演示账号密码随机生成且不输出，不提供固定登录凭据。

这是公共演示素材，不经过上传接口或用户配额，也不受私有媒体权限控制。内置 MP4 播放不代表用户视频上传功能已实现。

## 校验与重新下载

从仓库根目录执行：

```powershell
.\server\scripts\fetch-demo-assets.ps1 -VerifyOnly
```

仅验证本地文件和 SHA-256，不联网、不改文件。不带 VerifyOnly 时可下载缺失项，重建视频需要 PATH 中的 FFmpeg（本次使用 7.1.1）。已有文件不自动覆盖。上游文件或编码器版本变化可能导致哈希不同，脚本会报错，应重新核对来源，不可盲目更新校验值。

自动化测试验证所有文件哈希及图片尺寸、种子批次幂等、补齐 v2/v3 时保留已有作品与账号、保留用户草稿、头像及视频 Feed、Range/HEAD、署名和缺失文件响应；不代替 Android 真机播放验收。
