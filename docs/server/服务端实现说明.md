## 2. 工程结构

独立 Maven 工程，编译目标 Java 17。账号、作品复杂逻辑在业务 service；互动、事件、审核暂以控制器中的事务方法组织，扩展跨服务调用时再提取服务。Spring JDBC 使用参数绑定，未拼接用户输入作为 SQL 表名/列名。

auth 负责认证和会话，content 负责作品及 Feed，interaction 负责目标状态，events 负责事件及分析导出，moderation/users 负责管理员业务，common 负责统一错误；intelligence 当前提供本人画像代理，尚无推荐 Agent 网关。

采用 [Spring Boot 3.5 文档](https://docs.spring.io/spring-boot/3.5/reference/using/running-your-application.html)对应的 3.5.16，依赖由父 POM 管理，并执行本机 Maven 验证。

## 3. 数据与事务

|表|约束和用途|
|---|---|
|users|UUID 主键、用户名小写唯一、BCrypt、角色和 enabled|
|sessions|JWT jti 对应会话 ID；刷新令牌仅保存 SHA-256；7 天有效期|
|posts|自增 ID、作者外键、媒体 JSON、视频标识、状态、Unix 秒时间|
|interactions|用户+类型+对象复合主键；计数从记录计算|
|behavior_events|用户+eventId 唯一；seq 为导出游标；发生/接收时间分离|
|moderation_records|管理员、作品、前后状态、原因、时间|
|user_status_audit|管理员、用户、前后启用状态、原因、时间|
|media|上传者、真实宽高、重新编码的 PNG 字节及时间|
|post_media|作品与媒体关联、顺序；作品/媒体外键和位置唯一约束|

Flyway V1 创建业务表，V2 增加用户状态审计，V3 增加图片与关联表，V4 增加演示头像与批次，V5 增加事件时长/场景/来源、稳定导出序列及审计。不修改已应用迁移。默认 H2 文件数据库用于跨重启保存，测试使用独立内存数据库。

草稿编辑/状态变化锁定作品；同一用户的互动/事件写入锁定用户；唯一约束作最终防线。刷新在事务中锁定旧会话并消费后生成新会话。人工审核和审核日志同事务提交。

互动使用 `PUT {targetId, active}`，相同状态重复设置不重复计数。创建草稿暂不承诺幂等：超时重试可能生成多份，后续补 Idempotency-Key。编辑尚无 ETag/版本号，多端依次写入是后写覆盖前写。

## 4. 鉴权和错误

- 密码至少 10 字符、UTF-8 不超过 72 字节；BCrypt cost=12。
- HS256 JWT 有效 15 分钟，固定 issuer；每请求还查会话和账号状态，不是完全无状态认证。
- 安全随机 refresh token 有效 7 天且一次性轮换；刷新使旧 access token 同时失效。退出只注销当前会话，停用注销全部会话，启用不恢复旧 token。
- 身份取自 JWT，不接受 body 内的 userId、authorId、role。未知 JSON 字段拒绝处理。
- 管理操作仅 ADMIN；无权读非公开作品返回 404，修改他人作品返回 403。
- 仅支持 Authorization Bearer，不使用认证 Cookie，因此关闭 CSRF。尚未配置 Web CORS 白名单，联调时必须明确允许来源，不可无条件开放。
- 错误返回 status_code、code、message、requestId；经过安全过滤器的响应带 X-Request-Id。requestId 由服务端生成，异常不回显 SQL、堆栈或密钥。

默认只监听回环地址。公开部署前必须补 HTTPS、请求体限制、登录/注册限流、数据库身份、备份、日志保留及固定 JWT 密钥。过期会话清理、事件保留期和用户数据删除尚待实现。

## 5. 状态流转

```text
创建 → DRAFT ─提交→ PENDING ─人工通过→ PUBLISHED
                     └人工驳回→ REJECTED
作者撤回自己的作品 / 管理员下架已公开作品 → WITHDRAWN
DRAFT / REJECTED / WITHDRAWN ─编辑→ DRAFT ─提交→ PENDING
```

本版所有发布都人工审核，未接入安全 Skill 前不自动判定低风险。管理员不能直接批准未提交草稿。Feed 仅展示 PUBLISHED 且作者启用的作品；相同状态审核重试不追加重复记录。

媒体支持两条互斥输入路径：兼容外部 HTTP(S) clips 元数据，或使用本人上传的 mediaIds。外部 URL 不由服务端抓取，其校验不等于文件内容验证；本站上传媒体必须使用 mediaIds，防止绕过归属与可见性关联。允许空标题/无媒体保存草稿，发布时再校验完整性。话题提取与音乐仍未实现，对应 hashtag=[]、music=null；演示账号提供本地插画头像，普通账号头像编辑尚未实现。

图片上传识别实际 JPEG/PNG，解码前检查最大 400 万像素及单边 8192，输入和重新编码输出均限制为 8 MiB。忽略客户端文件名与 Content-Type，不保存原始文件名，不进行路径拼接；重新编码为 PNG，剥离原始元数据。Servlet multipart 请求上限 9 MiB，配置依据 [Spring 上传指南](https://spring.io/guides/gs/uploading-files/)。不宣称这是病毒扫描；视频/GIF/SVG 暂不支持，也尚未处理 EXIF 方向、相册 HEIC 或 WebP 转码。

图片字节与元数据同事务存入数据库，每用户最多 100 张。作品修改与 post_media 关联替换同事务完成。读取权限基于当前作品状态和作者 enabled；上传者/管理员可读私有图片，无权读取返回 404。no-store 避免共享缓存持续暴露，但不能撤回已下载副本；同图有其他公开作品关联时仍可公开。未关联图片可由本人手动删除，自动过期回收和对象存储待实现。

媒体管理接口 `GET /api/media` 仅列出本人记录，返回引用数及配额，可用 unusedOnly 筛选未引用项；分页按 UUID 字符串升序，新增/删除期间不保证固定快照。`DELETE /api/media/{id}` 只允许上传者删除无任何 post_media 引用的记录，成功 204、仍被引用 409、无权访问或已不存在 404。删除是永久数据库删除，无回收站；配额立即释放，数据库文件不一定缩小。

上传、作品创建/编辑及媒体删除统一先锁用户行，再按需锁作品并变更引用。这样删除与引用创建并发时，要么引用先提交并拒绝删除，要么删除先提交并拒绝引用；不依靠捕获外键错误来代替业务校验。草稿引用也受保护，下架作品不会自动释放引用，管理员无代删权限。

## 6. Feed 兼容约定

`GET /feed/?count=20&accept_video_clip=true&cursor=123`。

- 保留 status_code=0、整数 has_more、post_list，增加 next_cursor。
- count 为 1–50；查询 ID 小于 cursor 的作品，按 ID 降序。无 cursor 总是第一页，不在服务端保存共享翻页状态。
- 没有下一页时 next_cursor 为 null。客户端必须读取并回传游标。
- accept_video_clip=false 排除整个含视频作品，不删除单个片段。
- ID 顺序并非严格发布时间；并发发布/下架期间不承诺固定快照翻页。
- like_count 使用真实记录；Feed 和详情另提供 is_liked，按认证用户隔离，游客为 false。Android 已映射这些字段并移除随机点赞初始化，不再恢复旧的本地点赞缓存。
- 普通 Feed 暂不按 not-interested 记录排序或过滤；不能据此验收个性化推荐反馈。

新版种子使用本地 `/demo-assets/` 图片、头像与 MP4，署名和许可见[演示素材说明](演示素材说明.md)。`/demo-media/1.png` 至 `/demo-media/24.png` 保留给旧占位作品兼容使用。种子数据仅用于功能演示，不能作为推荐评测集。

## 7. 事件与 Python 边界

事件输入 eventId、postId、type、occurredAt（Unix 秒），userId 和 CLIENT 来源由服务端注入。允许 EXPOSURE、CLICK、DWELL、LIKE、FAVORITE、FOLLOW、SHARE、NOT_INTERESTED、PUBLISH；发生时间在最近 30 天至未来 5 分钟，必须关联已公开作品。可选 scene 为 HOME/DETAIL；DWELL 必须有 durationMs（1–1800000），非 DWELL 不得带时长。

同用户同 eventId 同载荷（含时长与场景）返回 duplicate=true；不同载荷 409。Python 去重键包含 source_id、user_id、event_id，不能只用 event_id。FOLLOW 关联来源作品，PUBLISH 是公开后的客户端事件，不代替提交审核记录。客户端遥测不得作为权限或审核事实依据。

`/api/admin/events?after=0&count=50` 仍仅供管理员人工导出。Python 改用 GET /api/internal/analytics/events，使用独立 PIXELFLOW_ANALYTICS_EXPORT_TOKEN（至少32字符）；仅有 events:read 权限，不能访问管理员或业务写接口，用户/管理员 JWT 不能读取内部导出。

LIKE/UNLIKE 的 SERVER 事件与点赞状态变化同事务写入，重复设置不重复发事件。Python 不使用客户端自报 LIKE 计算点赞权重。所有事件经 EventWriter 分配 seq，锁定 event_export_state 直至事务提交；导出同样锁定该行，避免并发事务提交乱序导致游标跳过尚未提交的事件。该全局锁适用于课程规模，不宣称具备生产吞吐能力。

导出含 source_id、items、next_cursor、has_more，并记录 event_export_audit。只导出分析所需的事件、作者 ID、媒体类型和当前公开标题；下架/作者停用后标题为空且 eligible=false，不导出密码、会话或作品正文。Python 将整页事件、画像快照和游标同事务落库，错误时不推进。源数据库变更需独立分析库，不能直接复用旧游标。

Python 已提供 POST /internal/sync 与 GET /profiles/me，使用两类独立认证（运维同步密钥、Java 用户 JWT）。默认手动逐页同步，没有自动调度；已有画像按新事件更新，非实时自动老化。运行步骤及数据规则见 [Python README](../../intelligence/README.md)。

推荐网关计划：Java 验证身份与开关 → 有超时的 Python 调用 → 重查候选可见性与负反馈 → 返回结果；异常/空结果退回普通 Feed并记录 traceId/原因。该链路尚未编码，不以普通 Feed 冒充 Agent 结果。
