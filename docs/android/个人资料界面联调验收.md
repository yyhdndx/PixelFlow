# Android 个人资料界面与服务端接入

日期：2026-10-22。基线 master `293e1c7`。开发工作树 `implement-android-profile`，分支 `feature/android-profile`；当前为本地未提交改动，未合并或推送。

## 本轮交付

- “我的”：真实头像、昵称、简介和本人作品/粉丝/关注统计，支持下拉刷新、加载状态、失败重试、未登录引导；不再使用旧 UserDataManager 的本机资料或128/2400/156模拟统计。统计未加载或失败显示“—”，成功返回0才显示0。
- “编辑资料”：独立页面编辑昵称和简介，输入计数、保存状态、离开时未保存确认；头像只读。ViewModel保留旋转前的草稿及正在执行的保存。保存失败不清空编辑内容，也不显示成功；先重新读取核对，若写入实际成功则确认完成，否则保留草稿供用户再次保存。
- 账号页：统一登录/注册表单和错误提示，登录后回到个人页；登录状态下可退出。密码和令牌不持久化，账号页继续禁止截图；会话仍只在内存中。
- 兴趣画像：从账号页移到个人空间的独立入口，使用Java现有画像接口，包含空态及重试；明确非实时规则分析。
- 视觉：浅色背景、紫色强调色、统一圆角卡片、输入框和按钮，个人页恢复常规系统状态栏。底部仅保留可用的“首页”和“我的”；首页继续提供创作入口，移除未接通的朋友/消息导航。

本轮不实现粉丝/关注列表、作者作品列表、收藏页面、创作服务端接入、头像上传或历史画像页面。三个统计当前仅展示数字，不伪装成已实现的列表入口；头像上传仍依赖独立后端分支。

## 接口映射

| 场景 | Java接口 |
| --- | --- |
| 本人资料 | GET `/api/users/me` |
| 保存昵称/简介 | PUT `/api/users/me`，只发送nickname和bio |
| 本人统计 | GET `/api/users/me/stats`，响应user_id必须与本次资料一致 |
| 兴趣画像 | GET `/api/users/me/profile` |
| 注册/登录/刷新/退出 | 原有 `/api/auth/*` |

请求继续通过CommunityClient串行队列和现有401刷新机制。只读请求在页面离开后取消；响应交付检查会话版本，页面还检查本轮请求编号，避免过期响应更新已离开的页面。账号退出后清空会话，下次个人页刷新先清空上个账号的资料、头像和数字。

`app/src/main/assets/api.properties` 保持用户提供的 `url=http://8.140.36.87`，Nginx默认80端口转发Java；修改assets后需要重新构建安装。已从开发机验证公网 `/health` 返回200/UP。测试没有在云端创建账号或修改业务数据；云端个人资料读写仍需用自己的测试账号进行联调。

## 手动联调

1. 使用本工作树构建安装；打开“我的”，确认未登录引导和“—”统计。
2. 登录自己的测试账号，核对昵称、简介、头像与真实统计。
3. 编辑昵称/简介并保存，返回后及再次进入应显示服务端内容；昵称最多40个UTF-16单元、简介最多60个，空简介允许。
4. 断网保存，应保留草稿且不显示保存成功；恢复网络后先点击重新读取核对，再决定是否保存。
5. 未保存返回应询问；旋转编辑页应保留草稿。
6. 退出并切换另一测试账号，确认头像、简介、数字不串号；进程重启后显示未登录。
