# 客户端缓存现状与预算（Android · 四级缓存 L1）

日期：2026-11-05
状态：实现文档，配套代码见 `feature/android-client-cache`。
对应需求：课设「中间件 / 四级缓存」的客户端（L1）层。

## 1. 目标

在不因 GC 导致掉帧、不增加 OOM 风险的前提下，让客户端缓存命中更高、冷启动更快、弱网可读。本文先盘点现状，给出内存预算的合理值，再补齐已知 gap。

## 2. 现状盘点（代码审查结果）

| 维度 | 现状 | 评价 |
| --- | --- | --- |
| 图片内存缓存 | Glide 4.16 默认配置，无 `AppGlideModule`；大小由 `MemorySizeCalculator` 自动算（≈0.33–0.4×可用堆） | 基本合理，但未针对本 App 显式设预算 |
| 图片磁盘缓存 | Glide 默认 DiskLruCache（≈250MB），瀑布流 `DiskCacheStrategy.ALL` | 合理 |
| 瀑布流卡片图 | `WaterfallAdapter` `.override(卡片宽高)` + `.centerCrop()` | 正确降采样 |
| 详情页大图 | `ImagePagerAdapter` `.dontTransform()` 无 `.override()` | 缺口：大图可能按原图解码 |
| 全屏大图 | `FullScreenMediaDialog`（PhotoView）`ALL` 无尺寸上限 | 缺口：原图解码，OOM 风险 |
| 私有图片 | `AccountMedia`/`UserProfileActivity` `.diskCacheStrategy(NONE).skipMemoryCache(true)` | 正确隔离 |
| 预加载 | `PreloadManager` 记账 LruCache（MAX=500，按条目），真正图片在 Glide 缓存 | 记账缓存非瓶颈 |
| Feed/详情 JSON | 无磁盘缓存，冷启动重新请求 | 待补（磁盘，不占内存） |
| 点赞/收藏状态 | `SerialStore`，只乐观回显，不恢复旧点赞 | 合理 |
| OkHttp HTTP 缓存 | `OkHttpClient` 未配置 `Cache` | 待补（磁盘） |
| 搜索历史/草稿 | SharedPreferences / Room | 合理 |

## 3. 内存占用估算

Bitmap 内存 = 宽 × 高 × 4 字节（ARGB_8888），1080p 屏为基准：

| 场景 | 尺寸 | 单张内存 |
| --- | --- | --- |
| 瀑布流卡片（竖图 3:4） | ≈540×720 | ≈1.5MB |
| 一屏可见 4–6 张 | — | 6–9MB |
| 详情页大图（3:4） | 1080×1440 | ≈6MB |
| 全屏原图（若 4000×3000 不解码降采样） | 4000×3000 | ≈48MB |
| 上传上限（Clip ≤16384） | 16384×16384 | ≈1GB，**必 OOM** |

结论：内存大头是图片 Bitmap，已交给 Glide 管理；真正的风险点是「未按展示尺寸解码」的详情/全屏大图。

## 4. 合理缓存大小

| 缓存 | 建议值 | 理由 |
| --- | --- | --- |
| Glide 内存缓存 | `maxMemory()/3`（≈0.33×堆），经 `AppGlideModule` 显式设置 | 默认 0.4 略激进；0.33 更保守，磁盘兜底，命中率损失小 |
| Glide 磁盘缓存 | 250MB | 磁盘不占内存，越大越好 |
| PreloadManager 记账缓存 | 500 条（≈100KB 元数据） | 非 Bitmap，可忽略 |
| 详情页图解码上限 | `.override(屏宽, 屏高)` | 按展示尺寸解码 |
| 全屏图解码上限 | `.override(2048, 2048)` | 平衡 5x 缩放清晰度与内存峰值（2048²×4=16MB） |
| 待补（磁盘，不占内存） | Feed JSON 磁盘缓存 + OkHttp HTTP Cache 50–100MB | 后续单独任务 |

## 5. 本次补齐的 gap

1. **新增 `AppGlideModule`（`GlideConfig`）**：显式设置内存缓存预算 `maxMemory()/3` 与磁盘缓存 250MB，统一全 App 的 Glide 预算。
2. **`PreloadManager.onTrimMemory` 补 `Glide.get(context).clearMemory()`**：内存紧张时真正释放 Glide 内存缓存，而不只是清记账缓存。
3. **`ImagePagerAdapter` 详情页图加 `.override(屏宽, 屏高)`**：杜绝大图按原图解码。
4. **`FullScreenMediaDialog` 全屏图加 `.override(2048, 2048)`**：给 PhotoView 定解码上限，避免 OOM。

## 6. 磁盘层缓存（已在本分支落地）

- ✅ Feed 首页 JSON 落磁盘（`FeedCache`，Java 序列化）+ 冷启动秒开/弱网兜底，按账号 key 隔离。
- ✅ OkHttp 配置 `Cache`（50MB，`ApiClient`/`CommunityClient`）+ 服务端公开只读接口按游客加 `Cache-Control: public, max-age=60`（登录用户 `no-store`，因点赞/收藏状态个性化）。

## 7. profile 测量方案（真机验证「合理值」）

1. **内存**：Memory Profiler 跑「冷启动 → 瀑布流滚 10 屏 → 开详情 → 开全屏」，记录 Java 堆峰值 + Native 堆（Bitmap）。
2. **掉帧**：`adb shell dumpsys gfxinfo com.PixelFlow.app` 看 `Janky frames`，或用 Macrobenchmark。
3. **预算对比**：`AppGlideModule` 的 factor 设 0.2 / 0.25 / 0.33 三档各跑一遍，画「内存缓存预算 ↔ 命中率 ↔ 内存峰值 ↔ 掉帧」曲线，选命中率不再明显上升、但内存/掉帧开始恶化的拐点。
