# 推荐闭环实现方案（首页接入个性化推荐）

> 背景：行为画像与规则推荐链路已实现（行为采集 → 画像同步 → 三 Skill 推荐预览），但首页尚未接入推荐交付，闭环断裂。
> 本文记录把「推荐预览」接成「首页个性化 Feed」的实现思路，供后续落地。

## 一、断点确认

| 端 | 现状 | 缺口 |
| --- | --- | --- |
| Python | `GET /recommendations/me/preview` 完整：profile_insight → candidate_recall → feed_rank，返回 `items`（post_id + 分项得分 + 理由） | 无 |
| Java | `RecommendationController` 只有偏好接口（preferences / blocked-authors / topic import），无「ID 补卡片」交付接口 | 缺交付接口 |
| Android | `CommunityClient` 只有偏好读写，无拉推荐 feed 的方法；`HomeFragment` 首屏普通 Feed 随机打乱 | 缺调用 + 缺接入 |

闭环 = **Java 交付接口 + Android 接入 + 运维确认定时任务**。

## 二、架构：Java 代理

```
Android ──GET /api/recommendations/me/feed──▶ Java
                                             │ ① 转发用户 token 调 Python /recommendations/me/preview
                                             │ ② 拿回 items(post_id + score + reason)
                                             │ ③ PostService 把 post_id 补成完整卡片 + 状态复核
                                             │ ④ 按推荐顺序返回卡片 + strategy/reason/version
                                             ▼
                                          Python 预览接口
```

不做「Android 直连 Python 再回 Java 取卡片」：会 N+1 请求 + 客户端逻辑复杂。Java 是业务唯一入口，代理 + 补卡片都在 Java。

## 三、三步工作

### ① Java 推荐交付接口（核心）

- 新增 `GET /api/recommendations/me/feed`（放 `RecommendationController`）。
- 流程：
  1. 从请求 `Authorization` header 取**用户 token**（不是 `PythonCopilotAdvisor` 的 service token，因为 Python 要拿它去 Java 校验身份），转发给 Python `/recommendations/me/preview`；
  2. 解析响应 `items`（post_id + 分项得分 + 理由）+ `strategy` / `reason` / `profile_version`；
  3. 用 `PostService.view()` 把每个 post_id 补成完整卡片（自带状态/权限复核，Python 返回里已撤回/私有作品被过滤）；
  4. 返回：卡片数组（保持推荐顺序）+ `strategy` + `reason` + `profile_version`。
- **降级**：Python 不可用/超时 → 返回普通 Feed 首屏（复用 `PythonCopilotAdvisor` 的 `Optional.empty()` 降级），首页不白屏。

### ② Android 接入

- `CommunityClient` 加 `getRecommendedFeed(callback)` → 调 `/api/recommendations/me/feed`。
- `HomeFragment`：推荐 Tab（或首屏）改调推荐接口，展示卡片 + 理由；**去掉首屏随机打乱**。
- 分页：推荐接口只给首屏 10 条（feed_rank 上限），向下滚动切回普通 Feed 续页，不改现有分页。

### ③ 运维确认 + 闭环验收

- 确认 Python 画像同步任务（systemd timer / cron）持续运行，否则画像恒空 → 推荐恒降级 popular。
- 验收：真机「浏览/点击/停留/点赞 → 等一轮同步 → 首页出现对应主题/作者」的闭环验证。

## 四、四个必须处理的坑

1. **token 转发**：Java→Python 带用户 token，controller 里 `request.getHeader("Authorization")` 取，别用 service token。
2. **ID→卡片复核**：Python `items` 可能含已撤回/私有作品，Java 补卡片时用 `view()` 过滤，但保持推荐排序。
3. **分页**：推荐只覆盖首屏 10 条，续页用普通 Feed，不硬做推荐分页（候选池仅 50 条）。
4. **首屏随机**：接入推荐后必须去掉普通 Feed 首屏随机打乱，否则推荐顺序被洗掉。

## 五、工作量估算

- Java 交付接口 + 代理 + 补卡片：0.5~1 天
- Android 接入 + 去随机：0.5 天
- 运维确认 + 真机闭环验收：0.5~1 天
- **合计 1.5~2.5 天**

## 六、待定契约（实现时细化）

- 交付接口请求/响应字段（卡片复用 feed 卡片结构，附 `strategy`/`reason`/`profile_version`）。
- Java→Python 代理的鉴权与超时预算（Python 预览预算 15s，Java 侧超时建议 20s）。
- 分页游标：推荐仅首屏，续页沿用普通 Feed 的 `cursor`。
