## 开发环境启动

Android 默认地址已改为 api.properties 中的 http://10.0.2.2:8080，供 Android 模拟器访问宿主机。Java 的媒体地址也必须使用模拟器可达地址。下面使用独立演示数据库，不修改已有数据库中的媒体 URL：

```powershell
cd server
mvn package
$env:PIXELFLOW_SEED='true'
$env:PIXELFLOW_PUBLIC_BASE_URL='http://10.0.2.2:8080'
$env:DB_URL='jdbc:h2:file:./runtime-data/android-demo;MODE=PostgreSQL;DATABASE_TO_LOWER=TRUE'
java -jar target/pixelflow-server-0.1.0.jar
```

真机使用电脑局域网 IP，同步修改客户端 url、PIXELFLOW_PUBLIC_BASE_URL，并显式配置 SERVER_ADDRESS 和防火墙。已有种子 URL 不随配置自动变化，切勿为重建素材而删除业务库。本地 HTTP 仅用于受控开发，不使用真实密码，不公开暴露服务；正式环境需要 HTTPS 和安全网络配置。

从仓库根目录构建：

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest
```

SDK 由本机环境或 Android Studio 配置，不提交个人路径。APK 位于 app/build/outputs/apk/debug/app-debug.apk。

## 会话与错误处理

CommunityClient 使用串行网络队列，避免同一 refresh token 被多个请求同时消费；请求具备超时与页面取消能力，不跟随重定向，不自动重试不确定的网络写入。请求和回调带会话代次检查，退出后的旧响应不能恢复账号或更新为成功结果。

令牌只在进程内存中保存，不写 SharedPreferences、Room 或页面实例状态；密码输入框不保存状态，账号页禁止截屏。进程终止后需重新登录，不宣称已实现持久登录。只有收到 401 才尝试一次令牌刷新，刷新返回 401 后清除会话；断网或响应丢失时可能需要手动退出并重新登录。

退出操作立即清除本机会话，再尝试服务端注销；失败会明确提示服务端注销未确认。不能把离线退出等同于服务端令牌已撤销。页面销毁取消请求也不能撤销服务端已经执行的注册/点赞操作。

点赞 PUT 是目标状态设置，重复设置不重复计数；如果 PUT 成功但随后读取详情失败，界面提示刷新确认，不能认定写入一定失败。列表返回首页或下拉刷新后重新对齐服务器。

## 首版行为遥测（2026-10-05）

已增加登录用户的首页卡片挂载曝光、进入详情点击，以及详情 onResume 到 onPause 的停留时长（1秒起报、最多30分钟）。这是粗略生命周期测量，不是可见比例/有效阅读识别；后台时间不计入，账号变化时丢弃跨账号停留。游客不采集。

客户端遥测是 best-effort：最多1项待发送、网络请求3秒超时，拥塞或失败会丢弃，不弹窗干扰业务，没有持久队列或离线补传。每次上报带 UUID、发生时间和 HOME/DETAIL 场景，不传 userId/source。同一次事件若重试必须复用 UUID；当前客户端不自动重试。

点赞/取消点赞不依赖上述遥测队列：Java 在互动事务内生成 SERVER LIKE/UNLIKE，重复设置不重复增加事件。因此取消点赞也能影响 Python 画像。遥测失败不代表点赞失败。

Android 构建及31项单元测试通过（含1项模板测试），新增2项测试检查游客不发送、字段无用户身份注入，以及遥测错误不阻断后续业务请求。仍需实际设备验证曝光与停留生命周期。

## 本人画像入口

在“我的 → 账号与登录 → 查看我的兴趣画像”查看最近同步快照的版本、主题分和冷启动提示。按钮调用 Java /api/users/me/profile，不让 Android 持有内部服务密钥或直接选择 userId。Java 需配置 PIXELFLOW_INTELLIGENCE_BASE_URL，并运行 Python 服务；同步仍由运维手动调用，按钮本身不会同步事件。

Python 未配置/不可用时显示错误，不能把空白响应当作空画像；刷新后重新取服务端数据。Java 交叉校验用户身份、禁止缓存及重定向。新增画像代理客户端测试后，Android 共32项测试通过；页面展示仍待设备验收。
