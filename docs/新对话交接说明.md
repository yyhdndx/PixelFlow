## 6. 新对话建议的工作方式

1. 先阅读本文件与 [后端现状/排期](后端现状与Android开发排期.md)，再明确本次任务。不要自动替用户推进所有待办。
2. 核对主目录 `git status --short`、`git log`、`git worktree list`；需要远程信息时 fetch。不要使用破坏式重置来“同步”。
3. 选好工作分支。新功能优先独立分支；任务 07 留给 Java 同学，不与其重复开发。只读审查不直接修复、留言、合并或部署。
4. 小范围修改，补契约和验收测试；测试用独立 `_test` 库，禁止用云端业务库跑清表测试。将通过、跳过、未验证的环境分别报告。
5. 分别报告本地实现、提交、推送、合并、部署状态；只有用户明确要求时再执行对应外部操作。特别注意 master 推送可能触发自动部署。
6. 每完成一个重要里程碑，更新本文件的提交、分支和待办状态，避免下一轮再次追溯整个聊天。
