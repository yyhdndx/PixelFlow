# 旧偏好迁移与修复验证

更新日期：2026-10-17。本文补充偏好统一后的升级步骤，不自动迁移工作区里的业务数据库。

## 本次修复

1. Java 事件导出使用明确列清单；Python Event 接受可空 recommendation_id，兼容没有该字段的旧事件，但仍拒绝未知字段。避免新增数据库列无意改变导出协议。
2. 推荐执行 profile_insight 前移除 suppressed_topics 对应的主题权重，不修改原始画像；撤销后恢复。作者和媒介偏好仍可使用，热门推荐也可能出现该主题，所以“抑制兴趣”不等于禁止该主题全部作品。
3. PreferenceService.read 在事务中锁定与所有偏好写操作相同的用户行，完整读取开关、版本及子表后释放，避免多次查询拼出不一致快照。Python 对两次偏好读取都检查归属，适配器严格校验版本、ID、列表长度及主题白名单。
4. 增加按账号的旧 SQLite 偏好检查/导入命令与 Java 原子导入端点。无强制覆盖或自动合并。
5. 冒烟脚本改为 Java 写、Python 读，增加主题抑制/撤销和真实旧库导入验证；反馈产生的新增 SERVER 事件纳入同步断言。

## 升级操作顺序

1. 暂停旧 Python 写入口和 Java 偏好管理操作，确认当前 Java/Python 对应同一业务来源。先备份 Java 业务库和旧 Python 分析库。SQLite 活跃时使用一致性备份工具；不要仅复制主文件而遗漏 WAL。源库仍保留用于回退。
2. 部署包含本次修复的服务；旧 Python 写入口保持410。不要删除 recommendation_preferences、recommendation_exclusions 或 recommendation_blocked_authors 历史表，分析同步/重算也不应清理这些表。
3. 对需要迁移的每个账号，用该账号当前有效的 Java access token 运行检查。用户 ID 由 /api/users/me 得到，不接受命令行任意 user_id。管理员 token 也只能迁移管理员本人，不能替代其他用户授权。
4. 检查结果 ready_no_changes 表示可以导入但未写入；核对备份与账号后加 --apply。already_matches 表示内容相同，不需写入；任何 conflict 或错误均停止该账号处理。
5. 通过 Java/Python GET 偏好核对个人化开关、作品排除、作者屏蔽，并实际预览一次；确认后恢复偏好写操作。保留备份，不自动删旧库。

从 intelligence 目录执行，提前从私有配置注入 JAVA_BASE_URL 和 PIXELFLOW_MIGRATION_USER_TOKEN（access token 原值，不带 Bearer 前缀）。不要把真实 token 放进命令行、截图或 Git：

```powershell
.\.venv\Scripts\python.exe -m pixelflow_intelligence.migrate_preferences --database D:\backups\legacy-analytics.sqlite3
# 核对检查结果、备份和账号后再显式导入：
.\.venv\Scripts\python.exe -m pixelflow_intelligence.migrate_preferences --database D:\backups\legacy-analytics.sqlite3 --apply
```

默认 Java 地址为 http://127.0.0.1:8080。远程必须 HTTPS；禁用代理和重定向，网络调用超时10秒。旧文件以 SQLite mode=ro 打开并在同一读事务读取全部偏好，不创建缺失文件、不写源库；较早版本没有作者屏蔽表时按空列表处理。

输出仅含状态、条目数量、个性化开关、Java 版本或稳定错误码，不打印用户 ID、作品/作者清单、令牌或上游错误正文。失败退出码1，检查成功/导入成功/已一致为0。状态含义不能只靠退出码区分，必须看 status。

## 导入端点及冲突规则

POST /api/recommendations/me/preferences/import，使用用户 access token。请求形状：

```json
{
  "source_user_id": "与当前账号一致的用户ID",
  "personalized": false,
  "excluded_post_ids": ["123"],
  "blocked_author_ids": ["author-id"]
}
```

端点不是一键覆盖接口，只允许下列两种情况：

- Java 偏好完全默认且 version=0：单事务导入开关、排除及作者屏蔽，实际变更版本只加1。
- Java 内容与旧库完全相同，且无主题抑制：视为幂等成功，版本不变，适用于响应丢失后重试。

其他情况返回409 PREFERENCE_MIGRATION_CONFLICT，不自动合并、不覆盖、不删除。包括已有无版本的 not-interested 记录、用户曾更改后恢复默认、或已有主题抑制。源用户与登录用户不一致返回403，重复/非法 ID、超过1000作品或500作者上限返回400。

发生冲突时，用只读方式查看旧库对应账号记录，并与 Java GET /api/recommendations/me/preferences 比较，由用户明确确认每项保留/撤销后通过普通偏好接口处理。旧库没有可靠的逐项修改时间，不能判断哪一份更新；不能以“并集最安全”为由恢复用户曾撤销的排除。没有历史表、账号 ID 不匹配或库属于另一业务来源时停止，不按昵称映射或生成新用户 ID。

历史作品可能已被删除/下架，迁移仍保存合法 ID 的排除意愿；不读取或暴露该作品，不授予访问权限。导入不伪造新的 NOT_INTERESTED 事件或点击数据，也不导入历史 version 作为当前 Java version。

每次账号导入由 Java 单事务提交。网络超时时可能已经成功，重跑命令会检查当前内容；若用户之后又改了偏好，则报告冲突而不是重新覆盖。多账号操作不是跨账号事务，应逐账号记录结果。若要回退，停止写入后依据两侧备份及后续业务变化制定恢复方案，不在在线业务库上直接清表。
