# Copilot 交互规则（产品口径）

本文记录已拍板的交互决策，Android 外壳、后端网关与测试都以此为准。
后端已实现：`POST /api/agent/copilot`、`POST /api/conversations/messages/batch`、草稿 `content_version` 乐观锁。

## 一、冲突：只提供「重新生成」

AI 生成期间用户自己改了内容，**不提供覆盖、也不提供部分应用**。

1. 应用 `UPDATE_DRAFT` 时携带生成时的 `content_version`；
2. 版本不一致，服务端返回 `409 VERSION_CONFLICT`；
3. 客户端把提案标记为失效，提示「内容已更新，需要重新生成」，只留一个按钮；
4. 用户点「重新生成」→ 用当前最新内容重新发起一次 Copilot 请求（携带最新 `content_version`）。

不实现：覆盖、只应用标题、逐段合并。理由：两种来源同时改同一段，合并结果无法解释，也没法追责。

评论与私信没有版本概念：评论是新建、私信是追加，不存在「覆盖别人的内容」，所以不走这条规则。

## 二、提案保留：一直留着，不设超时

- 生成的提案（POST_COMMENT / UPDATE_DRAFT / SEND_MESSAGES）在用户处理之前**一直保留**；
- 切换页面、收起对话层、退出详情页都不丢；
- 只有三种情况会消失：用户点「应用」、点「忽略」、或清空该会话；
- **提案不会自动执行**：离开页面时不会发评论、不会发私信、不会改草稿；
- 已知限制：提案存在客户端内存/本地存储里，**杀进程会丢**（不引入服务端持久化任务）。

后端不保存提案，也不做提案超时：提案的生命周期完全由客户端管理。

## 三、历史对话：本地保存 + 上下文标签

### 存哪
- 只存在客户端本地（推荐 SharedPreferences + JSON，或 Room），**不上传服务端**；
- 每个会话保留最近 20 轮消息，超出丢弃最早的一轮；
- 设置页提供「清空 AI 对话历史」，一键删除全部本地会话。

### 必须带上下文标签
每条会话都要能一眼看出「这是关于什么的对话」，标签由 `screen` + 目标生成：

| screen | 标签格式 | 示例 |
| --- | --- | --- |
| detail | `帖子《标题》` | 帖子《宿舍低预算做饭经验》 |
| create | `草稿《标题》` | 草稿《周末的面包》 |
| messages | `私信 · N 位联系人` | 私信 · 3 位联系人 |

补充规则：
- 标题为空时用「无标题帖子 / 无标题草稿」；
- 标题过长截断到 12 个字加「…」；
- 私信会话额外列出联系人昵称（最多 3 个，超出显示「等 N 人」）；
- 同一目标再次唤起 Copilot 时**复用同一会话**，不新开一条；
- 会话按「最近一次使用时间」倒序排列。

### 本地数据结构（建议）

```json
{
  "conversation_id": "local-uuid",
  "screen": "detail",
  "target": {"post_id": "98", "title": "宿舍低预算做饭经验"},
  "label": "帖子《宿舍低预算做饭经验》",
  "updated_at": 1762500000,
  "messages": [
    {"role": "user", "content": "帮我写条评论", "at": 1762499990},
    {"role": "assistant", "content": "帮你写了一条…", "at": 1762499995,
     "actions": [{"type": "POST_COMMENT", "text": "…", "status": "pending"}]}
  ]
}
```

`actions[].status` 取值：`pending` / `applied` / `ignored` / `stale`（冲突失效）。

### 与审计 trace 的区别
服务端仍会为每次调用写 agent trace（问题摘要、动作数、耗时、是否降级），仅管理员可见，用于排查；它**不是**用户可查看的对话历史，也不含完整私信内容。
