# PixelFlow 后续接口与实现方案

编写日期：2026-10-14。适用范围：Java、Python、Android、Web 管理端及 Agent/Skill/MCP 集成。

本文用于安排后续开发，不是已发布的 API 契约。标注“新增”“增强”“迁移”的内容均待实现；路径、字段和限额是建议冻结的设计。实施时先补 contracts 和测试，再实现服务及调用方。本文不变更运行配置或启动任务。

> 进度：任务1「偏好统一」已完成（2026-10-15）。第 4 节所列偏好相关接口已在 Java 落地，Python 旧写入口已停用，详见 [偏好统一完成说明](偏好统一-完成说明.md)。

## 1. 开发目标与优先顺序

下一阶段的重点是完成“用户反馈 → 推荐 Agent → Java 交付 → 客户端展示 → 管理员追踪”的完整流程，而不是继续零散增加分析接口。

|阶段|要完成的结果|涉及 Story|完成条件|
|---|---|---|---|
|A：统一数据与访问边界|推荐偏好以 Java 为唯一写入来源；候选查询、最终校验和降级都遵守同一份偏好|US-03/04/05/08|Python 不可用时仍能排除用户不想看的内容；不再双写两套反馈|
|B：推荐交付|Java 推荐入口、受控候选接口、快照分页、Android 推荐及偏好页面|US-02/04/05/08|真实登录用户可浏览带理由的推荐并反馈，普通 Feed 独立可用|
|C：课程智能能力|推荐 Agent、持久化 Trace、MCP Server、补齐两个 Skill|US-05/06|有动态工具选择和真实工具调用证据，不能把固定流水线当 Agent|
|D：管理与创作|创作预览与采纳、审核建议、Web 审核及运行监控|US-06/07|AI 只建议，用户确认草稿、管理员确认处罚|
|E：验收交付|事件归因、评测、部署和设备回归|US-01～08|可重复的一键启动、故障演示、测试报告与完整录屏|

阶段 A 必须先完成。阶段 B 与 C 可按契约分工推进，但课程验收必须包含 C，不能以纯规则推荐替代。最低目标仍为需求中的5个 Skill、1个 MCP Server、至少4个 MCP 工具。

## 3. 统一约定与责任边界

### 3.1 数据归属

- Java：账号、作品、媒体、互动、推荐偏好及其版本、客户端最终 Feed、人工审核、最终交付记录。
- Python：事件分析、画像版本、推荐算法、Agent 执行、Skill 和工具执行摘要。推荐偏好只作读取快照，不再独立接收正式业务写入。
- 模型：输出结构化计划和建议，不授予权限、不写数据库、不决定作品是否公开。
- 客户端只访问 Java；Python/MCP/维护接口不向 Android 或 Web 直接开放。

### 3.2 身份与内部接口

1. 客户端使用现有用户 access token；管理员接口继续由 Java 验证 ADMIN 角色及账号状态。
2. Java 调用 Python 用户级接口时转发该次用户 token，并额外携带独立的 `X-Service-Token`；Python 校验服务身份，再复用 Java `/api/users/me` 验证当前用户。不要相信正文中的 user_id、role 或 scopes。
3. Python 调用新增 Java 内部候选、偏好、校验接口时，同样需要独立服务身份和该次用户 token。服务权限按 candidates:read、preferences:read、delivery:check 等最小范围分配；读取型身份不能用于审核或反馈写入。
4. 这些是待实现的新访问规则。现有 AnalyticsSecurity 对 `/api/internal/**` 只放行事件导出，其他路径全部拒绝；新增接口必须增加独立匹配规则及越权测试，不能改为全部放行或复用 events:read 密钥。
5. 维护密钥继续只用于 `/internal/sync`、`/internal/profiles/refresh`、`/internal/status`。不要赋予用户反馈、管理员轨迹查询或内容写入权限。
6. 内网部署不等于免认证；跨主机部署使用 TLS，禁用重定向，禁止把凭据发往模型生成的 URL。

### 3.3 字段、错误及超时

- 新接口的 JSON 使用 snake_case；作品 ID 为正整数字符串，时间为 UTC Unix 秒。旧 Java 接口的 targetId、mediaIds、eventId 等保留原契约，由适配层显式转换，不全局改名。
- 保留已有 `/feed/` 和 `PostItem` 字段结构，推荐新增信息以附加字段承载，避免破坏普通浏览。
- 请求标识 requestId 表示一次 HTTP 请求；trace_id 表示一次 Agent 执行；recommendation_id 表示一批实际交付结果，三者不能互相代替。
- Java 对外错误继续兼容 ApiErrors；Python 新接口建议返回 `{code,message,request_id,retryable}`，由 Java 映射。已有 FastAPI detail 格式暂不隐式修改，另做兼容测试。
- 至少区分：401 会话失效、403 无权调用、409 版本/幂等冲突、410 推荐快照过期、422 参数错误、429 限流、502 上游格式错误、503 依赖不可用、504 总预算耗尽。
- 推荐按需求设计总预算不超过6秒：先给 Java 最终校验/本地降级预留时间，再分配 Python、规划器和工具的剩余预算。当前预览15秒协作式期限、每次 Java 请求5秒，不符合这个目标，不能原样作为正式接口。
- 6秒和降级1秒是待压测目标，不是当前性能结论。所有外部请求须有超时、响应体大小和返回条数限制；协作式 Skill 检查不等于可强行终止阻塞任务。

## 4. 推荐反馈与画像控制接口

### 4.1 Java 客户端入口

|方法与路径|类型|请求与响应要点|实现责任|
|---|---|---|---|
|GET /api/recommendations/me/preferences|新增|返回 personalized、excluded_post_ids、blocked_author_ids、suppressed_topics、version|Java 持有权威偏好；只返回本人数据|
|PUT /api/recommendations/me/preferences|新增|`{personalized:boolean}`，返回更新后的偏好|关闭后不使用画像排序，但全部排除规则仍生效|
|PUT /api/interactions/not-interested|增强已有|保持 `{targetId,active}`；可选 recommendationId、eventId 做推荐归因|同事务更新互动、偏好版本及服务端反馈事件|
|PUT /api/recommendations/me/blocked-authors/{author_id}|新增|`{blocked:boolean}`；返回偏好版本|推荐专用屏蔽，不是封禁或社交访问控制|
|PUT /api/users/me/profile/topics/{topic}|新增|`{suppressed:boolean}`，topic 必须在支持的主题集合中|记录兴趣标签抑制，不修改或删除原始行为事实|
|GET /api/users/me/profile|增强已有|附加有效主题与抑制说明，保留原始版本信息|展示时过滤已抑制主题；不得向其他用户查询画像|

“删除兴趣标签”的第一版语义为持久化抑制该主题的个性化权重，后续重算也不能自动恢复；不保证该主题作品永不出现在热门内容中，也不等同于删除全部个人数据。界面必须说明，并提供恢复操作。隐私数据彻底删除需要独立需求与删除流程，不混入这个接口。

### 4.2 数据实现与迁移

Java 新建推荐偏好主表及作者/主题子表，单作品排除复用 interactions 的 not-interested，避免第三份存储。实际变更才递增 version，重复设置不递增；同一用户写操作沿用锁定用户行的方式串行处理。

迁移步骤：先备份并生成差异清单 → 暂停两侧偏好写入 → 按用户核对并导入 → 对比数量/版本与排除结果 → 切换调用 → 禁止 Python 旧写入口 → 保留可恢复备份。Python 现有记录不包含完整修改时间，出现矛盾不能推断“最后一次操作”，也不能盲目合并后宣称保持用户意图；需人工确认冲突或让相关用户重新确认。

Python 旧接口保留一段兼容期时，只可代理 Java 或明确返回停用错误，不允许继续本地落盘。不要用无事务的 Java/Python 双写解决一致性。当前用户级偏好上限可沿用1000作品、500作者；超限返回409，不静默截断。

验收：只调用 Java 反馈接口后下一次推荐立即排除；撤销后恢复资格；关闭个性化仍过滤；同账号跨端一致；不同用户互不影响；Python 停机时 Java 降级仍遵守偏好。

## 5. 候选、排序与正式推荐交付

### 5.1 Java 内部数据接口（全部新增）

|方法与路径|输入|输出|约束|
|---|---|---|---|
|POST /api/internal/recommendation/candidates|topics≤10、author_ids≤20、media_type、count≤100、cursor|items、next_cursor、has_more、preferences_version|只读；公开作品、启用作者、用户排除和媒体类型在 SQL 中过滤；用户从认证上下文获取|
|GET /api/internal/recommendation/trending|count≤100、cursor、accept_video_clip|同上|首版明确按点赞数/时间规则排序，不叫全站实时热榜|
|GET /api/internal/recommendation/preferences|无业务参数|本人完整偏好快照和 version|供 Python/工具读取，不允许任意 user_id|
|POST /api/internal/recommendation/validate|post_ids≤100、expected_preferences_version|eligible_ids、current_preferences_version、changed|只检查资格，不触发 Agent，不把作者可见的私有详情当作公开推荐|

候选项至少包含现有 Skill 所需的 post_id、author_id、title、media_type、like_count、create_time、status、author_enabled。主题先复用规则分类；若要按主题高效检索，再落地 post_topics 派生索引，不能把“标题包含关键词”描述为向量检索。

标签/作者查询使用参数化 SQL，排序选项走枚举白名单。分页用稳定排序键组合而非 offset，游标绑定查询条件；分数变化时不承诺跨查询快照稳定。推荐最终分页由 Java 的交付快照负责。

### 5.2 Python 正式入口与 Java 网关

|方法与路径|类型|主要字段与责任|
|---|---|---|
|POST /agent/recommend|Python 新增|请求 `{goal,count,accept_video_clip,request_id}`；count 1～50，goal 为受限枚举 discover/follow_interests/explore；先不接受任意长指令。返回有序 items、reason、profile_version、preferences_version、policy_version、trace_id、degraded、fallback_reason|
|GET /api/recommendations/feed|Java 新增|用户登录必需；count、accept_video_clip、可选 cursor。首屏调用 Python，后续页读取交付快照，不重新排序|
|GET /api/recommendations/{recommendation_id}/posts/{post_id}/reason|Java 新增|只读本人实际交付过的推荐解释，返回简短原因及策略版本，不公开完整 Trace|

Python 返回项只包含作品 ID、排序分和短原因，不让模型生成标题、媒体 URL 或作者信息覆盖业务事实。Java 根据 ID 从业务库装配 PostItem、点赞状态和可访问媒体，保持原排序；不符合条件的作品移除，禁止使用详情接口的作者/管理员特权绕过公开检查。

Java Feed 响应建议形状如下（示意，不是现有接口响应）：

```json
{
  "status_code": 0,
  "has_more": 1,
  "next_cursor": "不透明分页令牌",
  "recommendation_id": "批次UUID",
  "trace_id": "执行UUID",
  "strategy": "personalized",
  "degraded": false,
  "fallback_reason": null,
  "post_list": [],
  "reasons": {"123": "与你近期的阅读兴趣相关"}
}
```

`post_list` 沿用现有字段，reasons 只包含本页真实交付的 ID。所有个性化响应 no-store。游客继续使用普通 `/feed/`，不要悄悄伪造用户画像。

### 5.3 分页与最终校验

建议 Java 持久化短期交付快照，首批最多100个 ID，默认10分钟过期；游标签名并绑定 user_id、recommendation_id、offset、媒体条件和偏好版本。客户端不能提交裸 offset 改查其他用户的结果。

每次翻页重新校验作品与作者状态。发现偏好版本变化，返回409 `PREFERENCES_CHANGED`，客户端清空旧分页并重新请求；到期返回410。已下架项可少返回，按扫描位置推进游标，不按实际返回条数推进导致重复。空页只要确实还有未扫描项即可 has_more=true，但客户端应有连续空页上限。

Java 最终读取权威偏好并完成资格检查；Python 内部校验只是提前过滤。不存在一次检查后永久有效的授权，打开作品和媒体时仍由 Java 校验。

### 5.4 故障降级

```text
Java 验证会话与偏好
  → Python Agent 规划与执行 → Java 最终校验 → 交付快照
            │超时/空结果/结果不合法
            └→ Java 本地热门或时间排序 → 同一套偏好与公开状态过滤 → 降级快照
```

身份失败直接401/403，不用热门结果掩盖鉴权问题。Java 无法读取自身权威偏好或业务库时返回503，不绕过排除规则。Python 失败可以本地降级；全部候选被合法排除时允许200空结果，不为凑数量放宽规则。降级只尝试一次，严禁 Java 降级再次调用 Agent 形成递归。

## 6. Agent、Skill、MCP 和执行轨迹

### 6.1 推荐 Agent 实现

在 intelligence/agents 中划分 planner、executor、policy、trace_store，复用 skills 注册表。planner 接收目标、允许的 Skill/工具描述和必要的结构化摘要，输出受约束的 plan；executor 负责执行，policy 负责身份、输入、调用预算、工具白名单和最终格式检查。

建议运行状态：CREATED → PLANNING → EXECUTING → SUCCEEDED / DEGRADED / FAILED。首版上限为6个执行节点、2次规划决策（初始计划和最多一次修正）；总时限受第3节预算控制。相同节点和参数不可无限重试，写工具不得自动重试除非具备业务幂等键。

至少验证三种不同决策：有效兴趣选择兴趣召回；冷启动或关闭个性化选择热门工具；候选不足时尝试另一受控来源并重新排序。Agent 必须实际根据上下文选择、调用并检查 Skill/工具；固定调用三函数仍只是规则流水线，可作为降级和对照组。

模型供应方、模型名称和 SDK 尚未确定，不在本文虚构可运行配置。先定义 Planner 接口和确定性测试替身，再用服务端密钥接入选定供应方；测试替身不能充当真实 Agent 验收证据。内容标题、正文、工具返回值都是不可信数据，不能作为改变工具权限的指令。

### 6.2 补齐两个 Skill

|Skill|输入|输出|实现及失败策略|
|---|---|---|---|
|content_safety|草稿标题、正文、标签、内容版本|risk_level、rule_hits、suggestions、requires_human_review、policy_version|先实现可测试规则，再可选模型辅助；失败标为 UNKNOWN 并转人工，不认定为安全；不可自动下架或封禁|
|creator_assist|草稿快照、受限创作目标、目标受众描述|候选标题/标签/修改建议及简短理由|长度限制、结构校验、安全检查；不覆盖草稿，失败保留原文；不伪造事实或引用|

两者必须通过现有注册表声明版本、Schema、scope、超时与降级，并覆盖正常、空结果、非法输出、超时和越权测试。不要在 Skill 中绕过 Java 写业务表。

### 6.3 MCP 工具契约

MCP Server 放在 intelligence/mcp。课程首版建议以 stdio 由受控 Agent 进程启动；stdin/stdout 专用于协议，日志走 stderr。部署需要独立远程服务时再确定传输和会话认证方案；不要用几个同名 HTTP 路由冒充完成 MCP 协议。

|工具|业务参数|绑定能力|授权和副作用|
|---|---|---|---|
|get_user_profile|无 user_id|读取当前用户有效画像及偏好版本|profile:read；只读|
|search_posts|主题/作者/媒体条件、数量/游标|Java candidates|candidates:read；只读|
|get_trending_posts|数量/游标/媒体条件|Java trending|candidates:read；只读|
|record_recommendation_feedback|post_id、active、recommendation_id、event_id|Java not-interested|feedback:write；只能执行用户明确确认的反馈|
|submit_moderation_suggestion|post_id、content_version、风险建议|Java 审核建议接口|moderation:suggest；仅写建议，不决定审核结果|

默认推荐 Agent 只授予前三个读取工具；提供4个以上工具不意味着每次推荐可以调用所有工具。写工具须有独立授权上下文和用户/管理员的明确业务操作，模型自行生成“确认=true”不算授权。

用户身份由父进程或受控服务会话绑定，不能出现在模型可改写的参数里。MCP 的工具参数、调用取消、错误响应和发现流程需通过真正的 MCP 客户端集成测试；具体 SDK 和协议版本实施前核实并锁定。

### 6.4 Trace 持久化与查看接口

|方法与路径|类型|能力|
|---|---|---|
|GET /api/admin/agent/traces|Java 新增代理|按时间、状态、场景分页，每页≤50|
|GET /api/admin/agent/traces/{trace_id}|Java 新增代理|管理员查看执行节点、耗时、业务计划摘要、降级原因|
|GET /internal/agent/traces|Python 新增|服务身份及已验证管理员身份，字段白名单过滤|
|GET /internal/agent/traces/{trace_id}|Python 新增|同上；普通用户即使猜到 ID 也无权访问|

Python 新增 agent_runs、skill_executions、tool_executions：记录 trace_id、受控 user_id、场景、状态、时间、依赖节点、Skill/工具版本、参数摘要、返回条数、错误码及降级类型。Java 另存交付记录关联 trace_id；Python 排过序不等于客户端实际收到或曝光。

只保存可审计的业务计划、输入输出摘要，不保存模型隐含推理、完整提示词、token、密码或无必要的原始草稿。输出脱敏规则需单测。建议保留30天可配置，并设置容量上限；自动清理前先完成备份与保留策略评审。

Trace 写入失败不能影响普通 Feed；Agent 接口应返回明确的 trace_unavailable 降级标记或降级 Feed，不能声称该 trace_id 已可查询。

## 7. 创作、审核与管理端

### 7.1 待新增接口

|方法与路径|角色|核心输入输出与实现|
|---|---|---|
|POST /api/agent/create-assist|草稿作者|draft_id、draft_version、goal；Java 校验归属并读取草稿，调用 Python，返回 suggestion_id、建议、risk、trace_id|
|POST /agent/create-assist|受控用户上下文|Java 提供的草稿快照；执行 creator_assist/content_safety，返回候选，不写原稿|
|POST /api/posts/{id}/assist-application|草稿作者|suggestion_id、selected_fields、expected_version、idempotency_key；确认后事务更新，版本不一致409|
|POST /api/admin/posts/{id}/safety-check|管理员|当前内容版本；生成/刷新安全建议，不自动审核|
|POST /api/internal/moderation/suggestions|授权建议服务|post_id、content_version、risk、rule_hits、summary、idempotency_key；只保存建议，旧版本拒绝|
|GET /api/admin/posts/{id}/suggestions|管理员|分页读取建议及对应内容版本|
|GET /api/admin/users/{id}/status-history|管理员|分页查询已存的用户启停审计记录|
|GET /api/admin/intelligence/status|管理员|代理 Python /internal/status；明确标识本地统计和上游未知状态|

当前 PostService 没有草稿内容版本字段，需要新增 version 并对编辑、提交发布、建议采纳实施乐观并发控制。建议必须绑定作者、草稿和版本，有期限；客户端不可把任意模型文本直接指定为“服务器建议”。过期或已采纳重复请求按幂等规则处理，不静默覆盖用户新编辑。

人工审核继续调用已有 `POST /api/admin/posts/{id}/moderation`；其状态转换和审核原因约束不由模型替代。内容修改后旧安全建议必须失效。第一版可在提交审核后运行安全检查，不因模型不可用阻断人工处理。

### 7.2 直接复用而不应重复开发的接口

- `/api/auth/*`、`GET /api/admin/users`、`PUT /api/admin/users/{id}/status`：Web 登录与用户管理。
- `GET /api/admin/posts`、`POST /api/admin/posts/{id}/moderation`、`GET /api/admin/moderation`：审核队列、决策与操作记录。
- `POST /api/media`、`POST/PUT /api/posts...`、publish/withdraw：Android 上传、草稿、提交审核和下架。
- `GET/PUT /api/interactions/{kind}`：客户端接收藏、关注和状态恢复。

当前上传服务只接 JPEG/PNG，不能把演示视频可播放理解为用户视频上传已完成。课程先交付图文创作闭环；若保留用户视频发布验收，再单独实现上传大小/时长限制、真实容器识别、封面与转码任务，不能直接信任客户端 URL/扩展名。

Web 首批页面按“登录 → 用户管理 → 审核队列/详情 → Trace → 汇总指标”实现。菜单隐藏不是授权；跨用户或普通用户访问管理员路径必须由服务端拒绝。先沿用现有接口完成页面，再新增页面真正缺少的查询条件。

## 8. 事件、反馈归因和指标

### 8.1 已有事件接口增强

保留 `POST /api/events`，新增可选 recommendationId、traceId、position。Java 校验 recommendationId 归属、作品确实在该批次交付、position 合法；客户端不能凭空指定策略版本，策略从交付记录取得。eventId 重试去重时也比较新增字段。

客户端负责曝光、点击、停留等观察事件；点赞/收藏/关注/不感兴趣等状态变更应由 Java 业务事务生成 SERVER 事件，不能靠客户端重复上报证明互动发生。当前仅点赞/取消点赞已做到状态变化发事件，其他类型需要补事件定义、取消语义与画像权重版本。

Android 待补：有容量上限的持久化发送队列、重试退避、事件 ID 复用、退出/换账号隔离、过期丢弃；曝光要定义可见比例与最短可见时长，不能继续把卡片 attach 视为真实阅读。改动事件契约时同步更新 Java 导出与 Python Event 模型，旧记录新增字段可为空。

### 8.2 待新增指标接口

|方法与路径|输入|输出及边界|
|---|---|---|
|GET /api/admin/analytics/recommendations|from、to、policy_version；最大31天|Java 验证管理员后代理汇总；禁止任意用户画像查询|
|GET /internal/analytics/recommendations|同上，内部授权|曝光量、点击率、点赞率、负反馈率、覆盖率、重复率、样本数、数据时间范围|
|GET /api/admin/analytics/agents|时间段、场景|成功/降级/失败次数，耗时分位数、Skill 错误数；无样本返回 null 或0并说明|
|GET /internal/analytics/agents|内部授权|从运行与节点记录聚合，不返回原始提示词|

首版归因口径建议：以 (user_id,recommendation_id,post_id) 去重曝光；点击/点赞/负反馈只统计真实曝光后24小时内、且属于同一次推荐的行为。同键重复不得增加分子分母；统计窗口未满需标为暂定。分母为0时比率 null，不伪装成0%。

覆盖率需要交付时的合格候选总量或可复现的候选集合；未保存时返回不可计算，而不是用“最近50条”冒充全库覆盖率。重复率定义为指定用户窗口内重复交付作品占比，并与同批重复率分开。候选筛除数、实际交付数、真实曝光数必须区分。

现有离线9场景评测可继续做规则回归，不替代上述真实行为指标。Agent 另加固定任务集，验证工具选择、非法工具拒绝、跨用户访问、提示注入、超时、空结果与降级，并记录模型/提示模板版本。
