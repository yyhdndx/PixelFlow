# [Java] 支持 Android「我的」页面读取与编辑个人资料

状态：待发布的 Issue 草稿，尚未创建 Gitee Issue。`01` 是本地任务顺序，不是线上编号。

建议负责：Java 同学；Android 同学负责后续页面接入和联合验收。优先级：P1。

## 前端需求

作为已登录用户，我希望「我的」页面显示当前账号的昵称、简介和头像，并能保存昵称与简介；重新登录后资料仍然存在，切换账号不会显示另一个账号的资料。

第一条任务只完成个人资料的最小读写闭环，不扩展为整套个人中心。

## 当前缺口

- Android 的 `ProfileFragment` 使用 `UserDataManager` 读取和修改本地资料，尚未与服务端账号资料同步。
- Java 已有 `GET /api/users/me`，返回 `id、username、nickname、role、enabled`；不需要重写登录注册。
- `users` 表已有 `nickname` 和 `avatar`，尚无简介字段，也没有本人资料编辑接口。
- `GET /api/users/me/profile` 是兴趣画像接口，本任务不占用或修改它。

## 本次接口约定（待实现）

### 1. 扩展 `GET /api/users/me`

需要登录，仅返回令牌所属用户。保留全部既有字段及类型，新增 `bio` 和 `avatar`；成功返回 HTTP 200，不额外套响应包装。

```json
{
  "id": "当前用户UUID",
  "username": "alice",
  "nickname": "小林",
  "role": "CREATOR",
  "enabled": true,
  "bio": "喜欢摄影和旅行",
  "avatar": ""
}
```

- `username` 是登录账号；界面可编辑的是 `nickname`，不要将两者混用。
- `bio` 无内容时为 `""`，不返回 `null`。
- `avatar` 返回现有头像 URL；没有头像时为 `""`，由 Android 使用默认图。本任务不新增头像上传。
- 本人资料响应设置 `Cache-Control: no-store`。

### 2. 新增 `PUT /api/users/me`

需要登录。请求仅包含两个必填的可编辑字段；这是对昵称和简介的完整替换，不是替换整个账号，也不支持省略字段的局部更新。

```json
{
  "nickname": "小林",
  "bio": "喜欢摄影和旅行"
}
```

- `nickname`：去除首尾空白后长度 1～40，不能全为空白。
- `bio`：长度 0～60，允许空字符串清空；保留输入的换行和空格，按纯文本存储和展示。
- 长度按 Java `String.length()` 的 UTF-16 代码单元计数，与当前 Android 文本计数方式一致；emoji 可能占多个单位，客户端需使用同一口径。
- 缺字段、`null`、错误类型、超长或空白昵称返回 HTTP 400，使用既有 `INVALID_ARGUMENT` 错误结构，不能部分保存。
- 明确拒绝额外字段，返回 HTTP 400；尤其不能通过 `id、userId、username、role、enabled、avatar` 修改身份、权限或其他资料。
- 目标用户只能取自认证上下文，不接受客户端指定用户 ID。
- 成功返回 HTTP 200，响应结构与上述 GET 一致，内容为保存后的资料，设置 `Cache-Control: no-store`。
- 重复提交相同资料保持相同业务结果。首版不做编辑版本冲突检测，多端并发采用最后成功写入覆盖。
- 未登录或令牌失效沿用现有 HTTP 401；账号停用等情况沿用现有鉴权规则，不新建一套认证机制。

## 实现建议

1. 在 `users` 增加 `bio` 字段，默认空字符串，使用新的 Flyway 迁移；不要修改已应用的历史迁移或要求清空数据库。
2. 扩展本人资料查询；编辑使用专用请求 DTO 和参数化更新，仅允许写入昵称、简介。
3. 两个字段在同一事务中保存，写入成功后返回一致的资料快照；不返回密码哈希、令牌等敏感字段。
4. 保持 `/api/users/me` 的身份查询兼容性，避免影响 Python 对用户身份的校验。
5. 同步更新 `contracts/http/java-api.yaml` 中本次接口及相关响应定义，补充自动化测试和少量调用示例即可，不另写全量接口规范。

## 验收条件

- [ ] 新注册用户 GET 能返回注册昵称、空简介以及头像字段，旧响应字段保持兼容。
- [ ] 修改昵称和简介后，再次 GET、退出重登后均可读到相同资料；用持久化测试库验证重启后仍保留，不能只改内存。
- [ ] 空简介可正常清空；缺字段、`null`、错误类型、空白昵称和超长输入返回 400，原资料不变。
- [ ] 覆盖长度边界、中文及 emoji 的计数测试，前后端不会出现不同长度规则。
- [ ] 匿名/失效令牌无法读写；账号 A 的更新不改变账号 B，额外身份/权限字段被拒绝。
- [ ] 修改昵称后，新请求的本人作品 Feed/详情中的作者昵称与个人资料一致；不要求已显示的旧页面实时推送更新。
- [ ] 既有登录、令牌刷新和身份查询相关测试仍通过；新增测试覆盖响应字段、校验、隔离和禁止缓存。
- [ ] PR 附 GET、PUT、错误请求示例及测试结果，说明迁移方式和联调启动步骤，不包含真实凭据。

## Android 接入时的配合事项

以下是后续前端任务，不要求 Java 同学同时修改 Android 页面：登录后从 GET 初始化资料；PUT 成功后以响应为准更新界面；失败不提示保存成功；切换账号或退出时清空旧资料，丢弃旧账号的迟到响应。不要把旧本地资料自动上传覆盖服务端。
