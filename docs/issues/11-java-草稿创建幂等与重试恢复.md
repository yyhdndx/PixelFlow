## 问题与目标

当前 `POST /api/posts` 每次调用都会在 `PostService.create()` 中新增作品。服务器提交成功但响应丢失时，客户端拿不到作品 ID，重试创建仍会生成第二份草稿。即使 Android 修复“创建成功、提交审核失败后复用 ID”，也无法仅凭客户端内存解决创建响应丢失。

为一次逻辑创建提供稳定请求键：同一用户以同一键重试相同内容，只得到同一作品 ID。提交审核继续是独立操作，不把创建与发布合并。

基线为最新已合入 master。F03 收藏字段及 Android 修复已本地验收，尚未提交，不作为本任务依赖；不要把无关 Android 改动一并合入。

2026-10-25 Android 协作更新：客户端已生成并持久保存 UUID 创建键，通过 `Idempotency-Key` 发送；已获得媒体/作品 ID 后复用，保存/审核失败先核对。由于本 Issue 尚未实现，未知创建结果暂时阻止再次 POST，提示到我的作品确认。后端交付后再启用同键重试并补真实联调；不能把已有请求头当作服务端幂等已经生效。见 [F04 客户端记录](../testing/F04-创作恢复与私有图片-2026-10-25.md)。

## 接口要求

扩展既有 `POST /api/posts`，请求体仍为现有 `Draft`，增加可选请求头 `Idempotency-Key`。

| 情况 | 预期 |
| --- | --- |
| 未提供请求头 | 保持原有接口行为，成功为 201，兼容旧客户端 |
| 首次有效键 | 原子创建草稿及幂等记录，返回 201 和完整作品 |
| 同一认证用户、同一键、相同逻辑请求 | 返回 200、同一作品 ID 及当前可读取状态，不新增作品或媒体关联，不重置已变化的状态 |
| 同一认证用户、同一键、不同内容 | 409，稳定错误码 `IDEMPOTENCY_CONFLICT`；不修改原作品 |
| 请求头为空、重复或格式非法 | 400 `INVALID_ARGUMENT` |
| 缺失/无效认证 | 按现有认证契约返回 401，不占用请求键 |

键格式约定为规范 UUID 文本，大小写规范化后存储；作用域必须包含认证用户 ID。不同用户使用同一 UUID 不共享记录。客户端不传用户 ID，也不通过键查询其他用户的作品。

请求一致性按校验后的业务字段计算：标题、正文、按顺序排列的 `mediaIds` 或兼容的 `clips`。JSON 属性顺序不得影响重放；媒体顺序、文本或媒体内容不同必须冲突。`null` 与省略字段按现有 `Draft` 的归一化规则处理，不自行增加去空白等语义变更。

已成功创建的请求重放不得再次校验成“创建另一份作品”，不得将已提交审核的作品恢复为 DRAFT。若原作品已不可读取，应返回明确错误，不能重建一份替代作品。首次版本不自动过期成功记录；后续清理策略另行约定，避免无提示地失去防重保障。

## 实现边界

- 幂等记录与作品、媒体关联在同一数据库事务中成功或回滚；依靠 `(user_id, request_key)` 唯一约束和一致的锁顺序处理并发，不使用进程内 Map 代替数据库约束。
- 校验失败、事务失败不留下占位记录；重试可恢复。并发争用应返回相同作品或确定的业务冲突，不泄露数据库异常为 500。
- 复用现有认证、媒体归属检查及作品可见性，不改变 `publish` / `withdraw` 的状态转换规则。
- 如新增表，追加 MySQL 和 H2 的新迁移；先协调迁移编号。独立头像分支已占用 V8，不能覆盖旧迁移或重复抢占 V8。
- 更新 `contracts/http/java-api.yaml` 的请求头、201/200/409 响应与示例，并提供 Android 重试调用样例。

主要位置：`PostController`、`PostService`、独立幂等存储/服务、Flyway 迁移与专门测试。不要扩展为所有接口的通用幂等框架，也不重写现有认证逻辑。

## 验收标准

- [ ] 同一键顺序重试只产生一条作品和一组媒体关联，返回 ID 相同。
- [ ] 至少 5 个并发相同请求最终只有一份草稿，没有 500；并发不同内容不能覆盖首次结果。
- [ ] 模拟首个响应丢失后用原键重试，能恢复同一作品；重启应用服务后仍能重放，不能只在当前进程有效。
- [ ] 相同键不同标题/正文/媒体顺序返回 409，数据库内容不变。
- [ ] 不同账号使用同一键互不影响；不能读取或修改其他账号的草稿。
- [ ] 非法媒体、未授权、事务中途失败都不残留成功记录；有效重试能够成功。
- [ ] 草稿已提交审核后重放创建，仍返回同一 ID，不重置状态、不再次审核。
- [ ] 无键旧调用仍保持原契约；不改变本人作品数组分页、公开作品/收藏卡片字段。
- [ ] 在隔离 H2 和 MySQL 8.4 测试库验证并发、回滚及迁移；验收报告列明运行/跳过数量。
