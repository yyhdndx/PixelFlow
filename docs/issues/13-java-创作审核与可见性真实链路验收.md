# [Java][P1] 验收图片创作、审核、公开展示与撤回的真实链路

## 背景与目标

Android 已在本地补齐媒体/草稿复用、编辑恢复及私有图片认证，但尚缺真实服务下的
“保存 → 重开 → 提交审核 → 审核通过 → Feed/作者主页展示 → 撤回”联调证据。
本任务交付可重复运行的 HTTP 集成测试和两账号演示步骤，发现问题时做最小后端修复。
不能仅靠直接调用 Service、MockMvc 或修改数据库状态证明真实链路通过。

## 工作范围

1. 使用 Java 17、MySQL 8.4 的独立测试库启动真实 HTTP 服务，准备作者 A、访问者 B 和管理员。
   普通用户通过注册/登录接口创建；管理员使用现有启动配置，凭据只注入本次测试进程。
2. A 上传合法 JPEG/PNG，保存带 `Idempotency-Key` 的草稿。模拟忽略首次成功响应，再用原键和
   原始请求重试，确认返回同一 `post_id`、媒体关联不重复。复用任务 11 的测试能力，不重新开发幂等层。
3. 通过 HTTP 重读、编辑和提交审核，确认 DRAFT → PENDING；重试提交不会直接公开。
4. 管理员通过既有审核接口批准，确认 PUBLISHED；A/B 可从相应公开入口读取。普通用户操作管理接口
   必须被拒绝，具体状态码以当前 OpenAPI 为准。
5. B 点赞、收藏该作品，检查公开详情、作者作品页和收藏页；A 撤回后，作品从公开列表及 B 的收藏页
   消失，B 无法读取私有详情；A 的本人作品仍保留同一 ID、WITHDRAWN 状态。
6. 使用另一份草稿覆盖“驳回 → 作者修改 → 再次提交 → 通过”，核对审核记录的前后状态。
7. 媒体可见性与作品状态一起验证：DRAFT/PENDING 时 A 可读、B/游客不可读；发布后可读；撤回后
   B/游客不可读。该图片不得同时被另一篇公开作品引用，否则不能据此要求图片变为私有。

## 实现边界与协作

- 推荐新增 `server/src/test/java/com/pixelflow/server/PostLifecycleHttpTest.java` 及 MySQL 专项；
  使用随机 HTTP 端口和测试内生成的小图片，不依赖外部图片站点、固定作品 ID 或共享账号。
- 所有业务状态变化通过 HTTP；数据库查询只用于核对记录数、关联及迁移，不能直接写 PUBLISHED
  或画像来跳过业务流程。管理员初始化除外，仍使用现有机制。
- MySQL 专项统一使用新变量 `MYSQL_TEST_POST_LIFECYCLE_URL`，指向独占、以 `_test` 结尾的库；
  共用 `MYSQL_TEST_USER` / `MYSQL_TEST_PASSWORD`。本地报告必须启用该专项，不能以跳过代替通过。
- 与任务 14 约定：Python 同学统一维护 `.github/workflows/backend.yml`，为上述变量提供独立 CI 库；
  本任务先交付测试及本地运行命令，不同时编辑该工作流。
- 不新增迁移，不改写 V1–V9，不合并头像分支，不改普通 Feed 为推荐流；当前迁移为 V1–V7、V9，
  V8 仍属未合入的头像工作，不通过占位迁移、repair 或 out-of-order 解决版本问题。
- 本地 Android 改动尚未提交，不作为本任务编译或运行依赖；Android 接入、真机及进程恢复由 Android 负责。
- 私有图片被拒绝时按现有 404 契约断言；不要扩大管理员、其他用户的访问权来让测试通过。

## 验收标准

- [ ] 同一次逻辑创建只生成一份作品，响应丢失重试可恢复原 ID；后续编辑/审核不重置幂等结果。
- [ ] 完整通过“上传、保存、重读、编辑、提交、批准、公开展示、撤回”真实 HTTP 链路。
- [ ] 驳回后可编辑再提交；重复审核不产生重复审核记录，非法流转保持既有错误契约。
- [ ] 非作者不能编辑/提交/撤回作品，普通用户不能审核；失败后作品状态不变。
- [ ] 本人作品、公开 Feed、作者公开作品、收藏列表与详情对各状态的可见性一致。
- [ ] 图片字节可读取且身份隔离正确；撤回后不能通过旧媒体 URL 绕过访问控制。
- [ ] Java 17 / MySQL 8.4 专项通过，记录实际运行、失败、跳过数量；必要时运行受影响的已有测试。
- [ ] 测试结束仅清理本次拥有的资源，失败也不污染其他测试；无共享/云端库写入。
