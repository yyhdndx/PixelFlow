## 2. 本 issue 必须交付的范围

### A. 流式协议（已定，三端按此实现）

沿用任务 27 的 SSE 约定，事件统一带递增 `seq`：

- 请求：`POST /api/agent/create-assist/stream`，body 与 `/api/agent/create-assist` 相同（`draft`/`goal`/`prompt`/`audience`/可选 `previous_result`），登录鉴权与长度限制一致。
- 事件：`delta`（`{"text": "…"}` 主字段纯文本增量）→ `done`（结构化最终结果 + `validated=true`）→ `error`（`code`/`message`/`incomplete=true`）。
- 流开始前的 HTTP 错误码沿用现有 `ASSIST_UNAVAILABLE`(503)/`ASSIST_INPUT_REQUIRED`(400)/`ASSIST_CONTENT_REQUIRED`(400)/`ASSIST_REVISION_REQUIRED`(400)；流开始后只能用流内 `error` 表达失败，不得改 HTTP 状态。
- 总预算不超 55 秒；空闲超时、总字节上限、取消规则沿用任务 27 的既有参数（`X-Remaining-Budget-Ms`、`X-Accel-Buffering: no`）。

**边界**：模型对单一目标输出纯文本，避免把结构化 JSON 逐字展示。`all`（综合优化）暂不走流式，仍用原完整响应。

### B. 流式范围（当前仅单一目标）

| goal | 流式主字段 | 完成事件附带 |
|---|---|---|
| `improve_title` | 标题（≤120） | tag_suggestions=[]、safety |
| `polish_content` / `write_content` | 正文（≤5000） | title_candidates=[]、safety |
| `suggest_tags` | 标签（空格分隔 `#tag`） | title/content_candidates=[]、safety |
| `all` | 不流式（一次返回标题+正文+标签） | — |

safety 复用确定性规则 `content_safety`，流结束后对生成文本计算，不随流逐字输出。

### C. 自动填入与内联操作

1. **自动填入**：完成后把 `title_candidates[0]` / `content_candidates[0]` 直接写入草稿标题/正文，并记录 `AssistUndo` 恢复点；生成期间草稿被用户改过则不覆盖（保留旧建议供复制，禁止静默覆盖新编辑）。
2. **撤销**：复用既有 `undoAssist`，恢复到生成前快照。
3. **继续修改**：内联按钮点击后弹出指令输入框（≤200），带 `previous_result` 调 `refineAssist` 继续生成。
4. **接受**：当前自动填入后即视为「已采用」，缺少显式确认按钮；需补一个显式「接受」按钮，语义为确认保留并收起操作区（不清空已填内容）。

## 3. 通用交互约定

- 首版只保证 App 进程存活时的页面切换与重建；不承诺杀进程后继续生成。
- 流式增量必须来自正在进行的生成，不得获取完整结果后用打字动画代替。
- 取消/失败/过期统一走既有 `AiTaskRegistry` 状态与 `assistMessage`，不重复造状态。
- 不向客户端发送模型密钥、内部提示或原始异常。
- 中断的部分内容不得作为完整建议采用；`error`/未 `done` 均视为未完成。

## 7. 2026-11-08：自动填入与按钮修复

本轮针对自动填入不显示、操作按钮缺失修复，尚不代表本 issue 全链路验收完成。

- 接受保留当前内容并收起操作区；撤销恢复本次生成前的标题与正文，存在后续手动编辑时先确认；继续修改沿用 previous_result。生成期间编辑过草稿仍不覆盖。
