## 2. 本 issue 必须交付的范围

### A. 修复并补齐现有任务管理（流式接线前完成）

源码已确认以下收尾点：

1. **首次请求无法启动的路径。** `AiTaskRegistry.Task` 默认状态为 `WAITING`，`isRunning()` 把它视为进行中；搜索、总结、规则提炼、文案页面在 `getOrCreate()` 后先判断 `isRunning()` 并返回，首次任务可能一直加载且没有网络请求。区分“新建但未提交”和“已入队/执行中”，统一实现原子的获取或启动，防止重复提交。
2. **页面恢复缺少结果订阅。** 当前注册表没有观察者机制，回调仍持有旧页面或旧视图。新页面找到运行中任务后只显示加载，任务完成时未必收到通知。由任务层持有结果，通过可解绑订阅通知当前页面；不让旧 Activity 长期被网络回调持有。
3. **跨问题与账号的迟到响应。** 搜索回调仅校验任务代次和页面是否销毁，没有完整验证当前展示的问题；账号清理目前取消并清空 Map，但未递增全部任务的代次。完善账号代次、当前任务身份及取消状态检查，取消后的回调不能更新 UI 或恢复旧状态。
4. **任务身份不足。** 搜索 key 只有问题文本，总结 key 只有作品 ID，其他场景使用输入的 `hashCode()`。按账号、场景、目标对象、输入版本及必要的会话/生成选项定义身份；不能仅靠有碰撞的短哈希判断两个输入相同。
5. **资源没有上限。** 单线程执行器仍可能无限排队，注册表 Map 无数量、大小、过期淘汰。增加有界等待与结果保留策略，队列满时给出可理解的状态；不要淘汰运行中任务却不取消网络资源。

保留普通写操作必要的顺序保障，确认并发后认证刷新正确。覆盖四类 AI 入口；已有文案输入快照检查和主动采纳逻辑应复用。

### B. 智能搜索端到端流式展示（首个演示闭环）

用户搜索后可以先看普通结果、打开原文；AI 来源和正文准备好后逐步显示，返回搜索页可继续查看。

先在 `contracts/http/java-api.yaml` 定义流式扩展，保留现有 `POST /api/agent/search` 完整响应行为。建议增加独立流式端点，路径与 Python 内部契约在开发前确定并记录，不能三端各自猜测。

契约至少写清：

- 请求的问题、可选会话，以及与原接口相同的登录鉴权和长度限制。
- 阶段、来源列表、文本增量、完成、错误事件的名称与 schema。
- `session_id`、`trace_id`、最终降级状态的返回时机；最后一次完整校验以什么事件确认。
- 流开始前的 HTTP 错误码；流开始后的错误事件；无完成事件就断开的处理方式。
- 总时限、空闲超时、响应上限、取消和重试规则。不得静默延长已有 55 秒整体预算。

分层实现：

| 负责侧 | 交付 |
|---|---|
| Python | 将检索和综合接入流式业务；复用并补齐 `stream_chat`；真实阶段提示；无结果直接明确说明；结束/失败的轨迹记录 |
| Java | 登录鉴权、参数和来源可见性校验、流式转发、错误映射、取消释放；不在 Java 重做检索或总结 |
| Android | 接收增量并更新任务状态；普通列表独立加载；来源可跳详情；重建后继续订阅；新问题不展示旧回答 |
| 网关/部署配置 | 对新增流式路由验证缓冲、读超时与断连处理，给出真实网关下的联调记录 |

必须保留的边界：

- 在输出来源及相关正文前完成权限检查，仅使用当前用户可见的 `PUBLISHED` 作品。最终再检查引用、完整性及来源状态；失效时不能将部分结果标为成功。
- 当前搜索模型提示要求 JSON，不能把它直接交给普通文本流后把 JSON 字符串显示在页面上；明确调整协议或实现增量解析。
- 核对 `stream_chat` 对截断结束（如 `finish_reason=length` 后出现 `[DONE]`）、无终止事件、错误事件、超大帧、总体字节上限和截止时间的处理；只有正常完整输出才可成功。
- 部分正文已经发送后不能再承诺改 HTTP 状态为 502，必须用流内错误/未完成状态表达。
- 中断内容不作为完整成功回答写入会话；故障轨迹仍应可核查。零结果和服务故障分别处理。
- 不向客户端发送模型密钥、内部提示或原始异常。

### C. 补齐其余三个已有前台场景

| 场景 | 剩余交互工作 | 完成标准 |
|---|---|---|
| 长文总结 | 当前仍是弹窗，改为作品内可收起区域；按作品版本保留结果；先概括、后完整要点 | 等待时可继续读原文/评论；收起再展开不重复生成；更换作品和原文修改不误用旧总结 |
| 文案生成 | 复用快照和采纳逻辑，补跨页恢复、输入变化提示、正文预览、完整候选才可采纳 | 继续编辑不被覆盖；旧输入建议可辨识；不同草稿/生成目标不串结果；放弃草稿取消任务 |
| 回复规则提炼 | 完整规则逐条校验展示；作者勾选/编辑后保存；任务与描述版本绑定 | 生成中仍能看已有规则；未确认不启用；重新生成不混入旧建议；不展示原始 JSON |

这三项可在搜索闭环后分 PR 推进。增量内容必须来自正在进行的生成，不能获取完整结果后用打字动画代替。结构化内容允许按完整块发布，不要求逐字显示半条规则。

## 3. 通用交互约定

- 首版只保证 App 进程仍存活时的页面切换与重建；不承诺杀进程后继续生成，不新增永久搜索历史。
- 收起区域、打开原文继续任务；提交新问题或主动停止时取消对应旧任务；退出账号清空账号相关任务与结果。
- 统一表达等待、准备、生成、完成、取消、中断和失败；不要在尚未执行时显示“模型正在生成”。
- 中断的部分内容标为未完成，禁止一键作为完整文案/规则采用。
- 用户向上阅读时不自动滚回底部；合并短时间内的 UI 更新，避免逐 token 刷新整页。
- 重试由用户明确触发；不得因页面返回、网络重连而无限重复调用模型。
