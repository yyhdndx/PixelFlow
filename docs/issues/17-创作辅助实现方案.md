# 17：创作辅助（Agent 创作辅助）实现方案

负责人：Android/集成负责人（Skill 与编排），Java 同学配合（草稿版本字段、交付接口）。编写日期 2026-10-30。

## 1. 目标与范围

让创作者在发布前获得「标题 / 标签 / 修改建议 / 写文案 + 内容安全检查」，建议以**候选形式**展示，只有用户确认后才写入草稿；模型失败保留原稿并提供跳过 AI 的路径。对应 US-06，P1。

首版采用**可测试的确定性规则**实现两个 Skill，不接大模型；模型辅助作为后续增强，不阻塞人工创作闭环。

## 2. 现状与缺口

已有：Java 草稿创建/编辑/提交审核/撤回（`PostController`）、Android 人工创作（`CreateWorkActivity` + `DraftEditorModel`）。

缺口（对照 US-06）：

| 项 | 现状 |
|---|---|
| `creator_assist` Skill | master 空目录 |
| `content_safety` Skill | master 空目录 |
| Java 建议生成/采纳接口 | 无 `assist`/`safety`/`suggestion` 相关代码 |
| 草稿内容版本字段 | `PostService` 无 version |
| Android 建议预览/确认 UI | 无 |

## 3. 总体链路

```text
Android 创作页「AI 建议」
   └─ POST /api/agent/create-assist   （Java：校验草稿归属 → 调 Python）
        └─ POST /agent/create-assist  （Python：组合 creator_assist + content_safety）
   └─ 预览候选建议（不写库）
用户确认
   └─ POST /api/posts/{id}/assist-application （Java：版本一致才写入）
```

## 4. 两个 Skill 详细设计

复用现有注册表：`Definition(name, description, scope, input_model, output_model, handler)`，`execute(data, context)`，失败抛 `SkillError`。

### 4.1 content_safety（内容安全）

- scope：`content:check`
- 输入 `ContentSafetyInput`：`user_id`、`title`(≤120)、`content`(≤5000)、`tags`(≤20 项，每项≤32)
- 输出 `ContentSafetyOutput`：`user_id`、`risk_level`、`rule_hits`、`suggestions`、`requires_human_review`、`policy_version`

规则（确定性、可测试，先不接模型）：

| 规则 ID | 判定 | 风险 |
|---|---|---|
| `banned_word` | 标题/正文/标签命中内置违禁词表 | high，`requires_human_review=true` |
| `contact_info` | 命中手机号 / 邮箱 / URL / 微信·QQ 引流特征 | medium |
| （无命中） | 全部未命中 | low，`rule_hits=[]` |

- 违禁词表内置在 Skill 内（首版约 10–20 个典型词，可配置），不访问数据库。
- `suggestions`：`banned_word` → 「含疑似违规内容，请修改后重新提交」；`contact_info` → 「正文含联系方式，可能被判定为广告」。
- `policy_version`：`content-safety-v1`。

### 4.2 creator_assist（创作辅助）

- scope：`content:assist`
- 输入 `CreateAssistInput`：`user_id`、`draft`（`title`/`content`/`tags`）、`goal`（受限枚举 `improve_title` / `suggest_tags` / `polish_content` / `write_content` / `all`）、`audience`(≤64，可空)、`prompt`(≤200，可空，写文案时作为主题)
- 输出 `CreateAssistOutput`：`user_id`、`title_candidates`、`tag_suggestions`、`edit_suggestions`、`content_candidates`、`policy_version`

规则（确定性，不接模型）：

| 目标 | 规则 |
|---|---|
| `improve_title` | 标题为空 → 用正文首句/前 20 字生成候选；标题 <5 字 → 建议扩充并给出「标题 + 首句关键词」候选 |
| `suggest_tags` | 从正文提取 `#话题`；正文与草稿均无话题时给出「建议添加标签」提示（规则版不接模型，不猜测关键词） |
| `polish_content` | 正文为空 → 建议补充描述；正文过短(<10 字) → 建议展开 |
| `write_content` | 从主题（`prompt` 优先，否则标题/正文首句）生成 1–3 条候选文案；规则版为模板生成，接模型后替换为自然文案 |
| `all` | `improve_title` + `suggest_tags` + `polish_content` 三项合并（不含 `write_content`） |

- 输出不覆盖原稿，只给候选与理由；`policy_version`：`creator-assist-v1`。
- 不访问网络/模型/数据库，草稿是调用方提供的可信快照。

### 4.3 通用错误语义

两个 Skill 与现有三 Skill 一致：`UNKNOWN_SKILL` / `FORBIDDEN` / `INVALID_INPUT` / `IDENTITY_MISMATCH` / `TIMEOUT` / `INVALID_OUTPUT` / `EXECUTION_FAILED`，由注册表统一处理。每个 Skill 至少覆盖正常、空输入、非法输出、超时、越权测试。

## 5. Java 接口与数据模型

| 方法与路径 | 责任 |
|---|---|
| `POST /api/agent/create-assist` | 校验草稿归属（作者本人）→ 读草稿 → 调 Python → 返回 `suggestion_id`、建议、风险、`trace_id` |
| `POST /api/posts/{id}/assist-application` | 作者确认采纳：`suggestion_id`、`selected_fields`、`expected_version`；版本不一致 409，幂等重复返回一致结果 |
| `POST /api/admin/posts/{id}/safety-check` | 管理员对当前内容版本生成/刷新安全建议 |

数据：`posts` 新增 `content_version`（乐观并发）。编辑、提交、采纳建议时递增；旧版本建议拒绝应用。Flyway 增量迁移，不改已执行迁移。

## 6. Python 端点

`POST /agent/create-assist`：受控用户上下文，Java 传入草稿快照，执行 `creator_assist` + `content_safety`，返回候选与安全建议，**不写原稿**。模型不可用或超时 → 返回结构化错误，Java 侧保留原稿并提示重试/跳过。

## 7. 失败与降级

- 模型/Skill 失败：保留用户原始草稿，返回可重试错误；用户可跳过 AI 直接提交。
- `content_safety` 失败：风险标记 `unknown` 并转人工审核，不当作安全通过；不自动下架或封禁。
- 凭据只存服务端，不落 Android 包、Web 静态资源、日志或 Git。

## 8. 测试计划

- Python：`intelligence/tests/test_creation_skills.py`，覆盖两个 Skill 的正常/空/越权/超时/非法输出，及规则命中样例（违禁词、联系方式、标题补全、标签提取）。
- Java：草稿版本并发（旧版本采纳 409）、越权（非作者不可建议/采纳）、幂等。
- Android：建议预览 → 确认写入 → 失败保留原稿 + 重试/跳过（设备测试）。
