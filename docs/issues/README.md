两人从最新 master 分别建功能分支，使用各自本地 MySQL 库，不用云端数据跑测试。任务 01 维护资料字段并协调 V7 迁移；任务 02 默认不改 UserController 或旧迁移。OpenAPI 是唯一预计会共同编辑的契约文件，分别维护路径和 schema，后合并者在最新 master 上核对双方改动。

03 使用独立 FavoritePostsController / FavoritePostsQueryService，默认不改 PostService 的公开行为；04 只新增 Python 包装器和调度模板，默认不改原 maintenance CLI。任务间没有功能上的前置依赖；这不代表 Git 合并绝不会冲突，特别是 01/02/03 的 OpenAPI 文件需要合并时协调。

01/02 可继续按现有分工推进；03、04 是额外可领取任务，不要求三人同时开四个任务。若一人负责 Java、一人负责 Python，01（或 02/03）与 04 是文件重叠最少的组合。优先完成在手任务，避免同一个人切换过多分支。

环境与交付要求见 [后端开发上手指南](../后端开发上手指南.md)。这里按可并行任务分配，不绑定长期职责，也不要求 Android 同学同时实现全部页面。新增任务默认不抢占 Flyway 迁移编号、不改共享认证逻辑、不直接发布到云端。
