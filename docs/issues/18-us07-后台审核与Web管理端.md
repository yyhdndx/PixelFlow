# [US-07][P0] 后台审核与 Web 管理端（双端硬指标）

负责人：WeiKnight（Gitee: @WeiKnight_CN）。状态：2026-10-31 已发布线上 Issue。
`18` 是仓库任务编号，线上 Gitee Issue：https://gitee.com/yyhSEU/pixel-flow/issues/IKRZQC

对应需求：US-07 后台审核；验收标准「工程复杂度」硬指标——双端 = PC 管理端 + 移动端用户端。
基线：最新 `origin/master`（`e6b1757`）。Java 侧审核、状态机与审计能力已存在，本任务只补管理端，
不重复实现后端业务。

## 背景与目标

`admin-web/` 目前只有目录骨架（`src/pages/` 下 auth、users、content、moderation、agent-traces、
analytics 均为空），README 标注「本期不开发」。验收标准要求 PC 管理端与移动端并存，且需求 US-07
要求管理员可审核内容、管理用户、查看 Agent 执行轨迹。本任务交付一个**最小可用**的 Vue 管理端，
跑通「管理员登录 → 审核队列 → 通过/驳回 → 状态留痕」主线，并预留用户与内容管理页面。

## 工作范围

1. 技术选型：Vue 3 + Vite + 轻量路由/状态管理（不引重型框架）；统一走 Java 既有 `/api/admin/**`
   接口（当前已要求 `hasRole("ADMIN")`），按 [OpenAPI 契约](../../contracts/http/java-api.yaml) 对齐。
2. 页面（最小集）：
   - 登录页：管理员账号登录，JWT 会话管理；
   - 审核队列：待审核作品列表（封面、标题、作者、提交时间），通过/驳回操作，状态与理由回显；
   - 用户列表：账号状态查看与启用/禁用；
   - Agent 轨迹页：trace 列表与详情（依赖 US-05 Trace 接口，可先占位、接口就绪后接入）。
3. 权限与边界：页面权限提示不替代服务端鉴权；Web 不持有模型密钥，不直连 Python 或 MCP 服务；
   所有写操作复用 Java 服务的鉴权与审计。
4. 工程化：提供 `npm run dev` / `npm run build`；README 补启动说明与管理员账号初始化指引。

## 实现边界与协作

- 只做 Web 管理端与联调，不改 Java 业务逻辑；发现接口缺口先记录并协商，不在本任务内扩接口
  （唯一例外：若 Agent trace 查询接口不存在，登记为 US-05 依赖而非自行实现）。
- 不实现评论管理、私信、数据大屏等非验收必需页面；页面美观达到整洁统一即可，可复用
  Android 端商用级重构的设计语言（圆角、主色、留白规范）。
- 数据库、部署脚本不在本任务；Docker Compose 统一交付另立任务。
- 两账号演示路径：作者 A 提交作品 → 管理员在 Web 端审核通过 → B 的 Feed 可见；驳回路径同样可演示。

## 验收标准

- [ ] 管理员可登录管理端，普通用户访问管理接口被正确拒绝（403）。
- [ ] 审核队列可完成「通过 / 驳回 → 再次提交 → 再审核」闭环，每次状态变化留审计记录。
- [ ] 用户启用/禁用即时生效，被禁用账号无法登录或调用业务接口。
- [ ] 管理端不直连 Python/MCP，不泄露任何密钥；构建产物可由静态服务器托管。
- [ ] 与 Android 端联动演示一次完整审核链路，录屏归档。
