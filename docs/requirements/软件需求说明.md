# PixelFlow Agent 智能社区软件需求说明

## 1 项目概述

### 1.1 项目背景

PixelFlow 是一个面向普通用户的 UGC 图文社区。用户可以通过双列瀑布流浏览图文和视频作品，进入详情页查看完整内容，也可以发布作品、关注作者并参与点赞、收藏等互动。

系统由 Android 用户端、Web 管理端、Java 核心业务服务和 Python 数据分析与智能服务组成。Java 服务负责账号权限、内容、互动和审核等事务型业务，Python 服务负责行为分析、用户画像、个性化推荐及 Agent 运行。Android 端服务社区用户，Web 端服务管理员，二者共同构成完整的社区业务系统。

项目以个性化推荐为主要智能场景，通过用户画像、可组合 Skill 和 MCP 工具实现社区推荐 Agent，并提供创作辅助、内容安全检查、推荐解释和人机协同审核能力。Agent 必须能够规划任务、选择 Skill、调用工具、校验结果、记录执行轨迹并在失败时降级，不能以单次大模型文本生成为主要实现。

### 1.2 项目名称

**PixelFlow Agent 智能社区：基于用户画像与可组合 Skill 的个性化 UGC 平台**

### 1.3 立项说明

本组拟开发包含 Android 用户端、Java 核心业务服务、Python 用户画像与推荐服务以及 Web 管理端的 PixelFlow 智能社区。系统将画像分析、候选召回、内容排序、内容安全和创作辅助等能力封装为可注册 Skill，由社区智能 Agent 根据用户目标和上下文选择 Skill，并通过 MCP 工具访问受控业务数据。项目包含账号与 RBAC、内容发布和互动、用户画像、Agent 推荐、创作辅助、后台审核和推荐评测共 8 条核心 User Story，形成可运行、可测试、可部署的中等规模软件系统。

## 2 建设目标与范围

### 2.1 建设目标

1. 使用 Java 服务提供稳定的 Feed、作品详情、内容发布和互动接口。
2. 建立账号、权限、内容、互动和审核等服务端业务闭环。
3. 使用 Python 服务采集和分析用户行为，生成可解释的动态用户画像。
4. 实现基于用户画像的个性化推荐，并提供推荐理由和反馈机制。
5. 实现具备规划、Skill 选择、工具调用、结果校验、执行追踪和故障降级能力的 Agent。
6. 提供轻量 Web 管理端，支持用户管理、内容审核和 Agent 运行情况查看。
7. 完成自动化测试、部署脚本、技术文档和演示材料。

### 2.2 范围边界

本期不实现即时聊天、直播、真实支付和复杂社交关系图谱；不训练大规模深度学习模型，优先采用内容特征、规则和轻量协同过滤完成可解释推荐；不允许生成式 AI 自动处罚用户或下架高风险内容，最终决定由管理员确认；不采集身份证、精确位置和通讯录等与课程目标无关的敏感信息。

如果项目进度出现风险，应优先保留账号与 RBAC、内容与互动闭环、用户画像、Agent-Skill-MCP、Web 管理端和可部署系统，再裁剪算法复杂度、非核心页面和视觉装饰。

## 3 用户角色与业务流程

### 3.1 用户角色

|角色|主要权限|
|---|---|
|游客|查看公开内容、注册和登录|
|普通用户|浏览个性化内容、点赞、收藏、关注、提交“不感兴趣”、查看和调整兴趣画像|
|创作者|拥有普通用户权限，并可创建草稿、发布、编辑和下架自己的作品，使用创作 Agent|
|管理员|管理用户状态、审核内容、查询审计记录、查看 Agent 执行轨迹和运营指标|

系统采用“用户—角色—权限”的 RBAC 模型。客户端是否显示按钮只用于改善体验，所有受保护操作都必须由 Java 服务端再次鉴权。

### 3.2 核心业务流程

1. 用户注册并登录，在 Android 客户端浏览社区内容。
2. 用户的曝光、点击、停留、点赞、收藏、关注和负反馈被记录为标准化行为事件。
3. Python 服务聚合行为数据，生成包含主题、作者和媒体偏好的用户画像。
4. 推荐 Agent 根据用户请求和画像选择召回、排序、过滤等 Skill，生成个性化 Feed。
5. 用户可以查看推荐理由、提交“不感兴趣”或调整画像，新的反馈进入下一轮推荐。
6. 创作者发布内容前可以使用创作 Agent 获取标题、标签和修改建议。
7. 内容安全 Skill 给出风险建议，高风险内容由管理员在 Web 端人工确认。

## 4 系统总体设计

### 4.1 系统组成

|子系统|建议技术|主要职责|
|---|---|---|
|Android 用户端|Java Android|内容浏览与发布、互动、推荐解释、画像反馈和创作 Agent 交互|
|Web 管理端|Vue 3 或等价轻量 Web 技术|管理员登录、用户管理、内容审核、Agent 轨迹和指标查看|
|Java 核心业务服务|Spring Boot、Spring Security、JPA/MyBatis|账号与 RBAC、内容、媒体元数据、互动、审核、Feed API 和 OpenAPI 文档|
|Python 分析与智能服务|FastAPI、pandas、scikit-learn 或等价技术|行为聚合、用户画像、候选召回、推荐排序、离线评测、Agent 与 Skill 运行|
|数据存储|MySQL/PostgreSQL，测试环境可使用兼容数据库|保存业务数据、分析特征、画像快照、推荐轨迹和审核记录|
|MCP 工具适配层|MCP SDK 或兼容实现|将 Java 和 Python 的受控能力暴露为 Agent 可调用工具|

### 4.2 服务职责边界

- Java 服务是业务事实来源，负责账号、权限、作品状态和互动结果等事务型数据。
- Python 服务负责分析和推荐，不直接绕过 Java 服务任意修改业务数据。
- Android 与 Web 端通过 Java REST API 完成业务操作。
- Agent 通过 Skill 和 MCP 工具读取所需数据，写操作必须复用服务端鉴权、审计和权限控制。
- 当 Python 服务、Agent 或模型接口不可用时，Java 服务仍需保证登录、普通 Feed、详情和人工发布等基础功能可用。

## 5 核心 User Stories

本期范围由以下 8 条核心 User Story 构成。每条 Story 都必须包含界面、接口、数据持久化和测试证据，不能只完成静态页面或算法脚本。

|Story|业务模块|优先级|主要依赖|
|---|---|---|---|
|US-01 账号注册登录与角色权限|账号与权限|P0|Java 服务、数据库|
|US-02 内容浏览与 Feed 服务|内容消费|P0|Java 服务、Android 客户端|
|US-03 内容发布与社区互动|内容生产与互动|P0|Java 服务、Android 客户端|
|US-04 行为采集与用户画像|数据分析|P0|事件规范、Python 服务|
|US-05 Agent 个性化推荐|智能推荐|P0|US-02、US-04|
|US-06 Agent 创作辅助|智能创作|P1|Agent、内容安全 Skill|
|US-07 Web 管理与内容审核|运营管理|P0|RBAC、内容服务、Agent Trace|
|US-08 推荐反馈与效果评估|反馈与评测|P1|画像版本、推荐轨迹、评测脚本|

### US-01 账号注册登录与角色权限

**作为** 游客，**我希望** 注册并登录 PixelFlow，**以便** 在自己的账号下使用社区功能；管理员希望系统能够按照角色限制受保护操作。

验收标准：

- 用户可以注册、登录、刷新令牌和退出，密码仅保存安全哈希。
- Android 端和 Web 端按照角色展示功能，Java 服务对接口执行 RBAC 校验。
- 普通用户访问管理员接口时返回明确的 401 或 403。
- 管理员可以启用或停用用户账号，操作写入审计日志。

### US-02 内容浏览与 Feed 服务

**作为** 社区用户，**我希望** 稳定浏览作品列表和详情，**以便** 快速发现并消费感兴趣的内容。

验收标准：

- Java 服务按照本需求定义的 `/feed/` 请求参数和响应结构提供内容列表。
- 新接口支持游标分页、作品详情和媒体元数据查询。
- Android 客户端可以通过配置切换到新服务。
- 首次加载、刷新、加载更多、空数据和请求失败均有明确状态。
- 系统提供足够的种子数据和用户发布数据，课堂演示不依赖外部内容服务。

### US-03 内容发布与社区互动

**作为** 创作者和普通用户，**我希望** 发布作品并进行点赞、收藏、关注和“不感兴趣”反馈，**以便** 完成真实社区互动并为推荐提供数据。

验收标准：

- 创作者可以创建草稿、选择媒体、发布、编辑和下架自己的作品。
- 点赞、收藏、关注和“不感兴趣”由 Java 服务持久化，重新登录后保持一致。
- 重复请求具备幂等处理，互动计数不会因网络重试重复累加。
- 未发布、审核拒绝或已下架内容不会出现在普通 Feed 中。

### US-04 行为采集与用户画像

**作为** 用户和推荐系统，**我希望** 将社区行为转化为可解释画像，**以便** 获得更符合兴趣的内容，同时能够了解系统如何描述我的偏好。

验收标准：

- 系统采集曝光、点击、停留、点赞、收藏、关注、分享、不感兴趣和发布事件。
- 行为事件至少包含 eventId、userId、postId、事件类型、发生时间和必要上下文。
- Python 服务生成主题偏好、作者偏好、媒体类型偏好、活跃时段和近期兴趣等画像特征。
- 每份画像带有版本号和生成时间，可以追踪变化。
- 用户可以查看画像摘要、删除兴趣标签或关闭个性化推荐。

### US-05 Agent 个性化推荐

**作为** 普通用户，**我希望** 获得与近期兴趣相关且不过度重复的内容，**以便** 更快找到有价值的社区作品。

验收标准：

- 推荐 Agent 根据请求上下文制定执行计划，而不是固定执行一次模型请求。
- Agent 至少组合调用画像、候选召回和排序 Skill 中的两个。
- 推荐结果包含作品、简短推荐理由、策略版本和 traceId。
- 已下架、无权查看和已标记不感兴趣的作品必须被过滤。
- 同一作者和同一主题设置重复度上限，避免推荐结果过于单一。
- Agent 或 Skill 超时、返回空结果或发生异常时，系统自动回退到热门或时间排序 Feed。
- 管理员可以根据 traceId 查看执行计划、Skill 调用、耗时和降级原因。

### US-06 Agent 创作辅助

**作为** 创作者，**我希望** Agent 根据草稿和目标受众给出标题、标签和内容修改建议，**以便** 降低创作门槛并改善表达质量。

验收标准：

- Agent 根据草稿选择创作辅助和内容安全等 Skill，并返回建议及理由。
- 生成内容先进入预览，只有用户确认后才能写入草稿或提交发布。
- 模型调用失败时保留用户原始草稿，并提供重试或跳过 AI 的路径。
- 模型凭据仅保存在服务端，Android 安装包、Web 静态资源、日志和 Git 中不得包含可用密钥。

### US-07 Web 管理与内容审核

**作为** 管理员，**我希望** 在 Web 管理端处理用户和内容审核任务，**以便** 维护社区内容质量并监督 Agent 运行。

验收标准：

- 管理员可以查询用户、作品、审核状态和操作记录。
- 内容安全 Skill 可以生成风险等级、命中规则和处理建议。
- 高风险作品的驳回或下架必须由管理员确认，不能由大模型自动执行。
- 管理员可以查看 Agent 成功率、Skill 耗时、失败次数、降级次数和推荐基础指标。
- 管理操作记录操作者、时间、对象、变更前后状态和原因。

### US-08 推荐反馈与效果评估

**作为** 普通用户和项目成员，**我希望** 能反馈推荐质量并量化推荐效果，**以便** 持续改进推荐策略。

验收标准：

- 用户可以查看“为什么推荐”、提交“不感兴趣”并撤销最近一次反馈。
- 显式反馈在下一次推荐中生效，并能在画像版本或推荐轨迹中找到依据。
- Python 服务输出点击率、点赞率、不感兴趣率、覆盖率和重复率等评测指标。
- 推荐策略保留版本号，同一测试数据集可以重复运行并生成对比结果。

## 6 功能需求

### 6.1 Android 用户端

#### 6.1.1 应用框架

- 底部导航包括首页、朋友、创作、消息和个人主页。
- 首页为默认页面；朋友和消息在第一版可以只保留入口和基础空状态。
- 首页顶部保留北京、团购、关注、社区、推荐和搜索入口，默认展示社区或推荐内容。
- 登录状态失效时，引导用户重新登录并保留可恢复的本地草稿。

#### 6.1.2 双列瀑布流

- 使用双列瀑布流展示图片和视频作品。
- 支持下拉刷新、上滑加载更多、首次请求失败提示和加载状态。
- 作品卡片展示封面、标题或正文摘要、作者头像、昵称和点赞数。
- 封面宽高比限制在 `3:4` 至 `4:3` 之间；标题最多显示两行，超出部分使用省略号。
- 卡片点赞操作立即更新界面，再由服务端确认；失败时回滚并提示用户。
- 推荐 Feed 可以展示简短的推荐理由，普通 Feed 不强制展示。

#### 6.1.3 作品详情

- 顶部展示返回按钮、作者头像、昵称和关注按钮。
- 底部展示快捷评论入口、点赞、评论、收藏和分享操作。
- 图片和视频片段使用横滑容器展示，支持片段级加载状态和失败状态。
- 多片段作品显示进度条，单片段作品不显示。
- 标题和正文完整展示，话题标签高亮并可进入话题页。
- 发布时间按 24 小时内、7 天内和更早日期三种规则展示。
- 支持列表卡片与详情页之间的共享元素转场；复杂跟手退出动画列为可选增强。
- 支持背景音乐、自动轮播和视频片段播放，并正确处理页面切换和前后台生命周期。

#### 6.1.4 内容创作

- 创作者可以输入标题、正文和话题标签，选择多张图片或视频并预览。
- 支持草稿保存、恢复、发布进度和失败重试。
- 创作 Agent 的建议以候选形式展示，不直接覆盖原文。
- 发布前展示内容安全检查结果；低风险内容可以继续提交，高风险内容进入人工审核。

#### 6.1.5 个人主页与画像控制

- 用户可以维护头像、昵称和个人简介，查看作品数、粉丝数和关注数。
- 用户可以查看兴趣画像摘要、删除兴趣标签、关闭个性化推荐。
- 关闭个性化推荐后，首页使用热门或时间排序策略，不继续使用个性化画像排序。

### 6.2 Java 核心业务服务

- 提供注册、登录、令牌刷新、退出和 RBAC 权限校验。
- 提供作品创建、查询、编辑、发布、下架和审核状态管理。
- 保存点赞、收藏、关注和负反馈，并保证重复请求幂等。
- 接收标准化行为事件，并向 Python 服务提供受控的数据访问接口。
- 提供 `/feed/` 接口和面向各业务模块的版本化 REST API。
- 统一返回错误码、requestId 和可读错误信息，并生成 OpenAPI 文档。
- 记录管理员操作和关键业务状态变更的审计日志。

### 6.3 Python 数据分析服务

- 按用户和时间窗口聚合行为事件，生成画像快照。
- 使用标题、正文、标签、作者和媒体类型等内容特征建立作品特征。
- 提供热门召回、内容召回和轻量协同召回中的至少两种方法。
- 根据用户画像、候选质量、内容时效性和重复度完成排序。
- 为推荐结果生成可解释的理由，不暴露内部提示词或其他用户数据。
- 提供离线评测脚本和固定测试数据集，支持策略版本对比。
- 提供画像、推荐、Agent 和评测相关 API。

### 6.4 Agent 与 Skill

#### 6.4.1 Agent 能力

Agent 必须具备以下完整执行过程：

1. 接收用户目标、身份和请求上下文。
2. 读取当前可用 Skill 的描述和约束，生成执行计划。
3. 选择一个或多个 Skill 或 MCP 工具并传入结构化参数。
4. 校验权限、参数、空结果和异常结果。
5. 合并执行结果并生成面向客户端的结构化响应。
6. 在模型或 Skill 失败时执行预设降级策略。
7. 保存 traceId、计划、Skill 名称与版本、耗时、结果摘要和失败原因。

仅调用一次大模型生成文本，或使用固定代码顺序调用推荐函数，不能单独作为 Agent 验收结果。

#### 6.4.2 Skill 规范

每个 Skill 必须声明名称、版本、用途、输入 Schema、输出 Schema、权限要求、超时时间和降级策略，并具有独立测试。

|Skill|输入|输出|用途|
|---|---|---|---|
|`profile_insight`|userId、时间窗口|兴趣标签权重、作者偏好、媒体偏好和活跃度|解释当前用户画像|
|`candidate_recall`|画像、数量和过滤条件|候选作品及召回来源|执行内容、热门或协同召回|
|`feed_rank`|用户特征、候选作品和上下文|有序作品、分数和理由|完成个性化排序与去重|
|`content_safety`|标题、正文和标签|风险等级、命中规则和处理建议|发布前检查和管理员审核辅助|
|`creator_assist`|创作草稿和目标受众|标题、标签建议和修改说明|辅助内容创作|

每个 Skill 至少覆盖正常结果、空结果和超时或异常三类测试。

#### 6.4.3 MCP 工具

项目至少实现一个可运行的 MCP Server，并暴露不少于 4 个工具：

- `get_user_profile`：读取指定用户的最新可用画像。
- `search_posts`：按照标签、作者、时间和作品状态检索内容。
- `get_trending_posts`：获取热门内容，用于普通推荐或故障降级。
- `record_recommendation_feedback`：记录显式推荐反馈。
- `submit_moderation_suggestion`：提交审核建议，最终处理仍由管理员确认。

MCP 工具必须执行身份校验、最小权限、输入验证、超时和审计，不能绕过业务服务直接修改数据库。

### 6.5 Web 管理端

- 提供管理员登录和基于角色的页面访问控制。
- 提供用户查询、启用和停用功能。
- 提供作品查询、审核、驳回和下架功能。
- 展示内容安全 Skill 的建议，并允许管理员填写人工处理原因。
- 支持按照 traceId 查询 Agent 计划、Skill 调用和降级记录。
- 展示 Agent 成功率、平均耗时、Skill 错误率和推荐评测指标。

## 8 接口需求

### 8.1 Java 服务接口

- `/api/auth/register`、`/api/auth/login`、`/api/auth/refresh`
- `/feed/`：获取社区内容列表
- `/api/posts`、`/api/posts/{id}`、`/api/posts/{id}/publish`
- `/api/interactions/likes`、`/favorites`、`/follows`、`/not-interested`
- `/api/events`：接收标准化行为事件
- `/api/admin/users`、`/api/admin/posts`、`/api/admin/moderation`

### 8.2 Python 服务接口

- `/analytics/profiles/{userId}`：读取画像摘要
- `/analytics/profiles/{userId}/refresh`：触发画像更新
- `/recommendations/feed`：生成候选和排序结果
- `/agent/recommend`：执行推荐 Agent 并返回 traceId
- `/agent/create-assist`：执行创作辅助 Agent
- `/analytics/evaluation`：生成推荐评测结果

### 8.3 Feed 数据结构

Feed 接口支持 `count` 和 `accept_video_clip` 参数，响应采用以下主要结构：

```json
{
  "status_code": 0,
  "has_more": 1,
  "post_list": [
    {
      "post_id": "100080",
      "title": "示例标题",
      "content": "示例正文 #示例话题",
      "hashtag": [{ "start": 5, "end": 10 }],
      "create_time": 1756289925,
      "author": {
        "user_id": "12306",
        "nickname": "示例用户",
        "avatar": "https://example.com/avatar.png"
      },
      "clips": [
        {
          "type": 0,
          "width": 1440,
          "height": 1920,
          "url": "https://example.com/image.jpg"
        }
      ],
      "music": {
        "volume": 100,
        "seek_time": 0,
        "url": "https://example.com/music.mp3"
      }
    }
  ]
}
```

Java 和 Python 服务的接口都应提供 OpenAPI 文档、统一错误码和请求标识。跨服务调用必须设置连接和读取超时，失败时按照业务要求降级，不得无限重试。

## 9 非功能需求

### 9.1 性能与可用性

- 在课程演示环境中，非 Agent Feed 接口的 P95 响应时间目标不高于 800 ms。
- Agent 推荐总耗时目标不高于 6 s；发生故障时，热门 Feed 降级响应目标不高于 1 s。
- 列表接口必须分页，媒体文件不得以 Base64 写入业务 JSON。
- Android 列表快速滚动时不得出现明显卡顿、持续黑屏或内存泄漏。
- Java、Python 或模型服务单点失败时，基础登录、浏览和人工发布仍应可用。

### 9.2 安全与隐私

- 密码使用 BCrypt、Argon2 或等价安全算法，令牌设置有效期和刷新机制。
- 模型密钥、数据库密码和 JWT 密钥只通过服务端环境变量或密钥文件注入。
- 任何发生暴露或误提交的凭据必须立即作废并轮换。
- 服务端校验上传文件的类型、大小和访问权限。
- 用户可以关闭个性化推荐、删除画像标签，并了解画像的主要来源。
- 日志和 Agent Trace 对令牌、密钥、密码和个人信息进行脱敏。

### 9.3 测试与可观测性

- Java 与 Python 服务分别具备核心业务单元测试和关键接口集成测试。
- Agent 使用固定测试集验证工具选择、结果格式、权限边界和降级行为。
- 不能仅以“生成结果看起来合理”作为 Agent 验收标准。
- 系统记录 requestId、traceId、耗时和错误码，支持定位跨服务问题。
- 提供 Docker Compose 或等价的一键部署方式和初始化数据脚本。

## 13 立项验收演示主线

1. 新用户注册并以普通用户身份登录 Android 客户端。
2. 用户浏览 Java 服务提供的 Feed，进入详情并完成点赞、关注和“不感兴趣”反馈。
3. 创作者创建作品，调用创作 Agent 获取标题和标签建议，确认后提交发布。
4. Python 服务根据行为生成画像，用户查看并调整自己的兴趣标签。
5. 推荐 Agent 制定计划，组合画像、召回和排序 Skill，返回带理由和 traceId 的个性化 Feed。
6. 人为制造一个 Skill 超时，系统返回热门 Feed 降级结果，基础浏览保持可用。
7. 管理员登录 Web 端完成人工审核，并查看 Agent Trace、Skill 耗时和推荐评测指标。
8. 项目成员运行自动化测试和一键部署脚本，展示完整工程交付。
