# 推荐规则离线回归评测

从 intelligence 目录执行：

```powershell
.\.venv\Scripts\python.exe -m pixelflow_intelligence.evaluation.recommendation
```

命令输出 JSON 摘要，全部场景通过返回退出码0，否则返回1。不访问网络、数据库、模型或真实用户数据，不写文件。需要先安装 intelligence 本地包及依赖。

## 样例与验收口径

数据版本 synthetic-recommendation-v1，固定时间1791000000，样例定义在 recommendation.py 的 fixtures()。九个场景为美食兴趣、数码兴趣、冷启动、过期画像、显式作品排除、非公开/禁用/未来内容与冲突去重、作者数量限制、主题数量限制、空候选池。每组明确声明期望作品顺序，策略变化后应先审查差异，不能仅为让测试通过而改期望值。

实际执行 profile_insight → candidate_recall → feed_rank。默认召回上限50、排序上限3、每作者2条、每主题3条；主题限制场景单独设为2，报告包含这个覆盖值。统一返回的数据版本、固定时间、参数、每场景结果和 policy_version 用于重复比较。trace_id 和耗时不纳入报告，避免非确定性字段干扰结果。

独立检查器不调用生产代码中的可见性过滤函数，检查重复 ID、非公开/作者禁用/未来内容、冲突快照、排除项、作者归属和数量限制。它检查的是样例快照，不替代 Java 实时权限校验；精确顺序断言另行验证整个流水线的结果。

## 热门基线与指标边界

基线使用同一候选池、排除项和数量限制，但不传画像，让相同流水线采用 popular 策略。不是另一套模型，也不是随机实验。

只有美食与数码两个场景提供人工指定的相关作品标签。hit_at_1 表示这两组中首位命中标签的比例；popular_baseline_hit_at_1 为对应基线比例。没有标签时返回 null，而不是虚构0。当前样例由开发者构造，专门验证偏好是否影响排序，没有独立留出集或真实反馈，不能把100%的样例命中称为生产推荐准确率、点击率提升或模型效果。

作者屏蔽、偏好持久化、身份校验、并发复核及真实 HTTP 调用由其他单元测试和 smoke_pipeline.py 验证，不包含在这九组纯 Skill 评测里。这也不是 Agent 评测：目前尚无模型规划或工具选择能力。
